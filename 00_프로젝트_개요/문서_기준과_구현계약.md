# dobedupop · mdrl 문서 기준과 구현 계약

- 기준일: 2026-10-12.
- 프로젝트명: `dobedupop`. 권리언어: `mdrl`(문서 제목의 MDRL 대문자 표기 허용).
- 현재 코드 패키지: `mdrl`, `rights-core`, `backoffice`. 루트 workspace: `dobedupop-platform`.
- 기존 digest·문서 형식·DB 도메인·ID 접두어는 데이터 계약이다. 제품명 변경과 함께 임의 치환하지 않는다.

## 1. 영역별 기준

| 판단할 질문 | 우선 기준 | 적용 방법 |
|---|---|---|
| 제품 목적·참여자·사업 범위 | 사용자 결정, 최신 사업기획 | 구현 범위와 사업의 목표 범위를 구별 |
| 공통 언어 개념·목표 | mdrl 언어레퍼런스북·코어 설계 | 문법·API는 실제 구현 계약과 함께 확인 |
| 현재 호출 가능한 API | package.json exports, 공개 타입, API 가이드 8장, tarball smoke | 패키지 루트 import 또는 미공개 내부 파일 의존 금지 |
| 현재 설치되는 DB 구조 | 순서대로 적용한 migrations | 데이터모델 문서만으로 테이블 존재를 가정하지 않음 |
| 현재 업무 상태·권한 | rights-core 서비스·routes·관련 시험 | 문서와 다르면 실행 상태와 목표를 별도 기록 |
| 현재 콘솔 기능 | React 라우트·API 호출·시험 | HTML 시안은 실제 API 연결의 증거가 아님 |
| 다음 Grant·프로파일 연결 | 통합 설계 베이스라인 v1.0 | 기존 통합 설계의 해당 확장 부분을 구체화. 신규 API·테이블은 미구현 |
| 과거 결정·검토 | 히스토리·아카이브·분석 스냅샷 | 당시의 사실로 보존, 최신 구현 지침과 구분 |

## 2. 현재와 목표

- 구현: Facts → Projection → Allocation → 정산 결과 → 원장 → 지급 시뮬레이터.
- 독립 라이브러리 구현: Grant 평가기, 프로파일 정의/레지스트리. 공개 export 제공.
- 후속 구현: Grant 판정의 발행·정산·지급 강제 적용, 버전별 제품 프로파일 검증·저장.
- 제품 프로파일 설계: 직접 권리자 중심, 출판사·신탁/관리단체·NFT 제외. 공통 언어의 PUBLISHER·CMO 및 기존 테스트 데이터를 삭제하지 않음.
- 보컬 조합 1차 구현: 단일 Work·선택 Stem 중심. 복수 Work·n차 파생·AI 확장은 별도 범위.
- 운영 준비: 개발 신원 `x-actor`, 파일 봉인 저장소, fake PSP를 실제 인증·오브젝트 저장소·실지급으로 교체하는 과제는 별도.

## 4. 변경 규칙

- 설계 변경: 문서 상태·버전·적용 범위와 미구현 항목을 명시.
- 공개 API 변경: exports·공개 타입·예제·tarball smoke를 함께 수정.
- DB 변경: 적용된 migration 수정 대신 신규 migration 추가. 데이터 이전·복원·호환 검증 포함.
- 봉인 형식 변경: 새 형식 버전과 기존 결과 재현 전략 필수. 과거 digest를 다시 써서 덮어쓰지 않음.
- 화면 변경: 기능 대응표의 구현 상태·API·시험 연결을 갱신.
- 파일 이동: 현재 진입점과 활성 문서의 링크 검증. 역사 기록의 옛 경로는 당시 기록으로 보존.
