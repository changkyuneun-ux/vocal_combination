# dobedupop 정합화 Implementation Plan

> **For agentic workers:** 실행 항목은 현재 세션에서 순서대로 처리한다. 코드 변경 검증은 test-driven-development 원칙을 적용한다.

**Goal:** 프로젝트 명칭·문서 기준·공개 API를 정합화하고 Grant·프로파일 통합 설계와 제품 기능 대응표를 확정한다.

**Architecture:** mdrl은 순수 계산, rights-core는 권한·저장·업무 상태, backoffice는 운영 UI를 담당한다. 통합 설계는 다음 개발의 기준이며 이번 작업에서 발행·정산 실행 동작은 변경하지 않는다.

**Tech Stack:** TypeScript, npm workspaces, Fastify, PostgreSQL, React.

**Spec:** [현재 구성 분석](프로젝트_구성과_상호연관성_분석_20261012.md).

## 범위와 결정

- 사용자 지정 명칭: dobedupop / mdrl.
- 2026-10-12 범위 확인: 정리와 통합 설계 확정까지. Grant 발행·정산 연결은 구현하지 않는다.
- 기존 저장 데이터의 digest·IR·DB 도메인은 변경하지 않는다.
- 역사 자료 본문은 보존하고 현재 진입점·활성 문서·패키지 계약만 수정한다.
- 이번 변경은 현재 폴더에 반영하며 커밋·외부 배포는 수행하지 않는다.

## Review Focus

- 이동한 폴더와 시안을 가리키는 링크의 존재 여부.
- 패키지 소스 직접 import로 가려진 배포 export 누락.
- API 예제의 Result 래퍼·필수 입력·타입 선언 정확성.
- 목표 설계를 현재 동작으로 오인할 수 있는 설명.
- Grant의 수권자·공동권리자·의무·철회·시점 누락에 따른 잘못된 허락.
