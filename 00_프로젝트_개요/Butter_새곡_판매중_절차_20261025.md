# BTS "Butter" — 새 곡 워크스페이스부터 판매 중까지 직접 처리하는 절차

작성 2026-10-25. 기준은 개발 서버(브랜치 `feat/works-ui`)이고, 2026-10-25에 이 절차를 개발 서버에서 처음부터 끝까지 실제로 따라 해 보았다. 팬 조합 발행까지 성공했다. 다만 화면만으로는 안 되는 곳이 있어서 그곳은 표시하고 우회 방법을 적었다(5절).

## 2. 시작 조건과 계정

- 빅히트 뮤직 테넌트가 **활성** 상태여야 한다(KYB 확인과 레이블·소속사 지급 정보는 개발 시드에 이미 들어 있다).
- 포털: http://localhost:5173/portal
- 지금 개발 시드에는 역할별 계정만 있고, 한 사람이 모든 권한을 가진 총괄 계정은 없다. 그래서 아래처럼 계정을 바꿔 가며 진행한다(5절 9번).

| 계정 | 하는 일 |
| --- | --- |
| usr_bh_rights(권리 편집) | 작가 등록, 새 곡, 권리·슬롯·스템, 계약, 팩 만들기 |
| usr_bh_policy(정책 편집) | 분배 규칙 만들기와 컴파일(IR 생성) |
| usr_bh_approver(승인) | 분배 규칙 승인 |
| usr_bh_activator(활성화) | 분배 규칙 활성화, 출시(팩 활성화) |
| usr_bh_admin(테넌트 관리) | 작가 지급 정보 |
| usr_member_*(멤버 7명) | 실연자 앱에서 확인·이용 동의·수령 위임 서명 |

**지켜야 할 두 가지**
- 이용 동의와 이용허락의 **시작일은 오늘(개발 시계) 이전**으로 넣는다. 날짜가 늦으면 "유효한 동의 없음" 차단이 생겨 활성화가 막힌다.
- **컴파일(IR 생성)은 곡 진행 ①~④가 모두 ✓가 된 뒤에** 한다. 확인이 덜 끝난 상태로도 컴파일은 되지만, 그 IR v1은 미완성인 채로 봉인된다.

## 3. 절차

곡 화면 위쪽의 곡 진행 띠(①~⑤)로 지금 어디까지 왔는지 확인한다.

### ① 원본 계약서 · ② 권리 등록

| 단계 | 화면 · 계정 | 할 일 | 확인할 것 |
| --- | --- | --- | --- |
| 1. 작가 등록 | `/portal/registry/parties` · usr_bh_rights | 작가 7명을 유형 AUTHOR로 등록한다(당사자 id·표시명). **사이드 메뉴에 없어서 주소로 직접 연다**(5절 5번) | 명부에 7명 |
| 2. 새 곡 ① 곡·녹음 | 작품 목록 › "+ 새 곡 워크스페이스" | 곡 Butter, 녹음 Original, 마스터 보유 "빅히트 뮤직 — 레이블", 녹음 계약서 PDF를 끌어 놓고 저장 | 녹음 권리 100% 확정, 원본 계약서 1 |
| 3. 새 곡 ② 원곡 권리 | 마법사 ② | "+ 작가"로 7명을 고르고 "균등 분배", 작품 계약서 PDF를 올리고 저장 | 합계 100%, 작가 7명에게 확인 요청 |
| 4. 새 곡 ③ 멤버 | 마법사 ③ | 멤버 7명 체크 → 저장. **지금은 저장 오류가 난다**(5절 1번, 우회 필요) | 보이스 7·소유 주장 7 |
| 5. 새 곡 ④ 확인 | 마법사 ④ → "워크스페이스로" | 원곡 권리 탭으로 이동 | 띠 ①✓ ②✓ ③ "작가 7 서명 대기 · 멤버 7 확인 대기" |
| 6. 슬롯·파트 | 원곡 권리 탭 · usr_bh_rights | "+ 슬롯 추가"로 1절의 슬롯 10개를 만들고, 슬롯마다 "파트 추가"로 원곡 담당과 시간을 넣는다 | 슬롯 10 · 보컬 파트 17 |
| 7. 스템 | 스템 탭 | 빈 칸을 누르면 그 자리 값이 채워진 추가 폼이 열린다. 원곡 스템 17개와 추가 녹음 3개를 넣고 WAV를 끌어 놓는다. **지금은 실연 주장이 다른 곡 보이스에 걸린다**(5절 2번) | 스템 20, 오디오 검사 READY |

## 4. 다른 앱이 필요한 곳

- **실연자 앱(멤버 7명)**: 확인 요청 확인, 팬앱 이용 동의, 수령 위임 서명.
- **작가 전자서명**: 실제로는 이메일 링크로 서명한다. 개발 환경에서는 포털 `/portal/contracts`의 "공급자 서명(개발)" 버튼이 대신한다.
- **운영 앱**: 빅히트가 이미 활성이므로 필요 없다. 새 테넌트라면 KYB 확인·활성과 레이블·소속사 지급 정보가 먼저 필요하다.

## 5. 지금 화면만으로는 안 되는 곳(2026-10-25 따라 해 보기)

| # | 막히는 곳 | 원인 | 우회(지금) | 고칠 방향(제안) |
| --- | --- | --- | --- | --- |
| 1 | 마법사 ③ 멤버 저장 오류 | 보이스 id를 멤버마다 하나(`voc_<멤버>`)로 만들어서, Dynamite에 이미 있는 id와 겹친다 | 이 곡 전용 보이스(`voc_butter_<멤버>`)를 API로 만든다 | 보이스를 곡 단위로 둔다 |
| 2 | 스템 추가의 실연 주장이 다른 곡 보이스에 걸린다 | 1과 같은 원인 | 스템과 실연 주장을 API로 등록한다 | 1과 함께 고친다 |
| 3 | 작품 이용허락 두 번째 작가부터 오류 | 계약 id가 `템플릿_곡`으로만 만들어져 작가끼리 겹친다 | 작가별 id를 붙여 API로 보낸다 | 계약 id에 상대 당사자를 붙인다 |
| 4 | 작가용 권리 확인서는 계약서 불러오기로만 만든다 | 계약 만들기 칸에 권리 확인서 템플릿이 없고, 가짜 PDF는 읽기 틀이 못 읽는다 | API로 보낸다 | 계약 만들기 칸에서도 권리 확인서를 고를 수 있게 한다 |
| 5 | 작가 등록 화면이 메뉴에 없다 | 옛 화면만 남아 있다 | `/portal/registry/parties` 주소로 연다 | 운영 관리 › 조직 › 내 조직의 당사자 표에 등록 버튼을 둔다 |
| 6 | 작가 지급 정보 화면이 없다 | 포털 화면이 없다 | API로 한다(빠뜨리면 경고만 남고 활성화는 된다) | 당사자 상세에 지급 정보 칸을 둔다 |
| 7 | 날짜를 늦게 넣으면 활성화가 막힌다 | 시작일이 개발 시계보다 늦다 | 시작일을 오늘 이전으로 넣는다 | 입력 칸 안내와 기본값을 오늘로 한다 |
| 8 | ①~④가 끝나기 전에도 컴파일이 된다 | 확인이 덜 끝났는지 검사하지 않는다 | ①~④가 다 ✓가 된 뒤 컴파일한다 | 확인이 덜 끝났으면 컴파일 버튼을 끄고 안내한다 |
| 9 | 한 사람으로 끝까지 할 수 없다 | 시드에 총괄(RIGHTS_ALL) 계정이 없고, 정책 편집·승인·활성화를 서로 다른 사람이 하게 하는 직무 분리 규칙이 켜져 있다 | 계정 4개를 바꿔 가며 한다 | 결정 RD6("직무 분리는 지금 적용하지 않음")대로 규칙을 끄고, 총괄 계정을 시드에 넣는다 |

1~6번은 개발 환경에서 API를 직접 부르는 우회가 필요하다. 그 호출을 그대로 다시 돌릴 수 있는 스크립트는 시험 작업 폴더에 있다(`butter.mjs`, 메인 세션 scratchpad).
