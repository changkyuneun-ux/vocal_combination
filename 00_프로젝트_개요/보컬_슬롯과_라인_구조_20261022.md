# 슬롯(원곡 흐름)과 파트 구조 — 2차 이용은 슬롯의 스템 배치를 바꾸는 것

- 작성일: 2026-10-22 (같은 날 개정: 슬롯 = 원곡의 전체 흐름 구간, 연주·보컬 구분 없음)
- 요청(사용자):
  - 슬롯은 원곡에서 정한 전체 흐름 정보다(Intro → Verse 1 → Pre-Chorus → Chorus → Verse 2 (Rap) → Pre-Chorus → Chorus → Break (Dance) → Chorus (전조) → Outro). 연주·보컬을 구분하지 않는다
  - 2차 창작·이용은 이 슬롯의 오리지널을 바꾸는(다른 멤버 보컬 등) 스템 배치다
  - 원곡 권리의 실연 정보는 슬롯 기준으로 나뉘어야 하고, 한 슬롯에 여러 멤버가 있으면 그 멤버들을 모두 관리해야 한다
  - 필요하면 DB·MDRL 설계를 바꾼다
- 관련: [E10~E11 IR 연계와 CRUD](E10_E11_IR_연계와_CRUD_20261022.md), [MVP E2E 흐름과 화면 매핑](MVP_E2E_흐름과_화면_매핑_20261022.md), 시안 캔버스 "곡 워크스페이스 v2" 줄

## 지금 구조와 문제

| 지금 | 문제 |
| --- | --- |
| 슬롯 하나 = 멤버 한 명이 원곡에서 부른 파트를 모두 합친 것(`slt_part_jungkook` 등 7개, 연속 구간으로 근사) + 곡 전체 길이의 MR 슬롯 | 원곡의 흐름(Intro·Verse·Chorus…)과 맞지 않는다. 한 구간에 여러 멤버가 있는 경우를 나타낼 수 없다 |
| 스템 = (슬롯, 부른 멤버), 반주는 곡 전체 스템 하나 | 구간 안의 어느 목소리를 바꾸는지 구분할 수 없다. 구간별 반주를 바꿀 수 없다 |
| 발행 배정 = 슬롯마다 스템 하나(`snapshot_stem_assignment` PK가 snapshot·slot) | 구간 안의 여러 파트를 각각 바꿀 수 없다 |
| 원곡 담당 멤버는 슬롯 id 이름에만 있다 | 원곡 배치를 데이터로 알 수 없다 |

## 새 구조

```
곡 → 녹음 → 슬롯(원곡 흐름의 구간, 시간순 — 연주·보컬 구분 없음)
                └ 파트(그 구간을 이루는 원곡 트랙: 보컬 파트 0..n, 연주 파트 1..n)
                      └ 원곡 담당(보컬이면 멤버) · 파트의 시작~끝
                      └ 스템(그 파트를 채우는 녹음: 원곡 스템 + 다른 멤버가 부른 추가 녹음 스템)
```

- **슬롯** = 원곡의 흐름 구간 하나. Dynamite는 10개: Intro · Verse 1 · Pre-Chorus · Chorus · Verse 2 (Rap) · Pre-Chorus · Chorus · Break (Dance) · Chorus (전조) · Outro. 시작·끝은 원곡 음원의 실제 시각이고, 순서는 원곡이 정한다. 연주만 있는 구간(Intro·Break)도 같은 슬롯이다
- **파트** = 그 슬롯을 이루는 원곡 트랙 하나.
  - 보컬 파트: 그 구간에서 한 멤버가 부른 부분. 구간 안에서 차례로 부르면 파트가 차례로, 함께 부르면(화음·제창) 시간이 겹친다. 파트마다 원곡 담당 멤버, 역할(리드·화음·애드리브·제창·랩), 구간 안의 시작~끝이 있다
  - 연주 파트: 그 구간의 반주(필요하면 악기별로 나눈다). 원곡 담당 멤버가 없다
- **스템** = 어떤 파트를 채우는 녹음 하나. 원곡에서 그 파트를 낸 녹음이 원곡 스템, 다른 멤버가 같은 파트를 부른 녹음이 추가 녹음 스템
- **2차 이용(조합)** = 슬롯마다, 파트마다 스템을 고르는 배치. 아무것도 바꾸지 않은 배치가 원곡이다. 예: Chorus의 지민 파트를 진의 스템으로 바꾸면 그 조합은 "Chorus에서 진이 지민 파트를 부른 배치"다

## DB 변경

| 표 | 변경 |
| --- | --- |
| `part_slot` | 열 추가: `section_label`(Intro·Verse 1…). 시작·끝은 원곡 실제 시각, 순서 유일성은 그대로. 연주·보컬 종류 열은 두지 않는다 |
| `slot_part`(새) | `slot_id`, `part_no`, `kind`(`VOCAL`·`GROUP`·`INSTRUMENT` — `GROUP`은 전원 제창·애드리브, 교체 불가·사용 시간 제외, SL7), `role`(`LEAD`·`HARMONY`·`ADLIB`·`UNISON`·`RAP`·연주는 NULL), `start_ms`·`end_ms`(구간 안, 겹칠 수 있음), `original_party_id`(보컬이면 원곡 담당 멤버, 연주면 NULL). PK(slot_id, part_no) |
| `stem` | 열 추가: `part_no`. FK(slot_id, part_no) → `slot_part`. 곡 전체 길이의 MR 스템은 없애고 슬롯별 연주 파트 스템으로 나눈다 |
| `snapshot_stem_assignment` | 열 추가: `part_no`. PK (snapshot_id, slot_id) → (snapshot_id, slot_id, part_no). 사용 시간은 파트의 시작~끝 |
| 이전(마이그레이션) | 기존 슬롯마다 파트 1(보컬, 원곡 담당 = 슬롯 이름의 멤버, 시작~끝 = 슬롯 전체)을 만들고 기존 스템·배정을 파트 1로 옮긴다. MR 슬롯은 연주 파트 1 |

## 코어 변경

- **발행 검사:** "슬롯 중복 금지"를 "같은 (슬롯, 파트) 중복 금지"로. 모든 슬롯의 모든 파트를 채워야 한다(빠지면 `PART_MISSING`). 스템이 그 슬롯·파트의 스템인지 확인한다
- **사용 시간(조합 지분 IR의 입력):** 스템별 사용 시간 = 그 파트의 길이(파트 끝 − 시작). 연주 파트와 그룹 파트(SL7)는 사용 시간에 넣지 않는다. 그룹 파트는 배정에서 원곡 그룹 스템으로 고정된다. 화음처럼 시간이 겹치면 겹친 시간을 각자 부른 시간으로 센다
- **함께 만드는 실연 주장(ID3):** 보컬 스템 등록 때 스템 → 부른 멤버의 보이스 주장. 연주 스템은 실연 주장 없음(녹음 권리만)
- **확인 요청:** 파트의 원곡 담당 지정도 멤버 확인 대상(SL3)
- **팬 채널 API:** 배정을 `{slotId, partNo, stemId}`로. `partNo`가 없으면 파트 1(하위 호환). 바꾸지 않은 파트는 원곡 스템으로 채우는 기본값을 화면이 넣는다
- **정합성 규칙:** 파트에 원곡 스템이 없으면 경고, 보컬 파트의 원곡 담당 멤버에게 보이스가 없으면 차단

## MDRL 변경

- 엔진은 계산에 슬롯을 쓰지 않는다(몫은 스템별 사용 시간으로 계산한다). 바뀌는 것은 facts 문서의 스템 항목뿐이다
- facts `Stem`에 선택 항목 `part`(파트 번호 문자열)를 더한다. 검증·텍스트 형식(`stem … { of; slot; part; rights_bearing; }`)에 반영한다
- 파트가 하나뿐인 슬롯은 적지 않으므로 **기존 facts digest는 바뀌지 않는다**(SL4). 정책·조합 지분·멤버 IR 형식은 그대로

## Dynamite 데이터

- 슬롯 10개(흐름)는 사용자가 정했다. 각 슬롯의 보컬 파트별 담당 멤버와 시각은 공개 자료에서 확인하지 못했다(멤버별 총 가창 시간만 있음). 빅히트 원본 크레딧·가사 배분 자료로 입력한다(SL5). 시안은 "가정 데이터"로 표시한다
- 사용 시간이 파트 길이로 바뀌므로 Dynamite 예시 보고서의 금액이 달라진다. 새 데이터로 예시 보고서·시험 기대값을 다시 만든다
