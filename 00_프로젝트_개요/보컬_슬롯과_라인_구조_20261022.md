# 보컬 슬롯과 라인 구조 — 한 구간을 여러 멤버가 부르는 경우

- 작성일: 2026-10-22
- 요청(사용자): 원곡 권리의 실연 정보는 **보컬 슬롯(곡 구간) 기준**으로 나뉘어야 하고, 한 슬롯을 여러 멤버가 부르면 그 멤버들을 모두 관리해야 한다. 그래야 슬롯별 스템(보이스) 등록과 조합이 된다. 필요하면 DB·MDRL 설계를 바꾼다
- 관련: [E10~E11 IR 연계와 CRUD](E10_E11_IR_연계와_CRUD_20261022.md), [MVP E2E 흐름과 화면 매핑](MVP_E2E_흐름과_화면_매핑_20261022.md), 시안 캔버스 "곡 워크스페이스 v2" 줄

## 지금 구조와 문제

| 지금 | 문제 |
| --- | --- |
| 슬롯 하나 = 멤버 한 명이 원곡에서 부른 파트를 모두 합친 것(`slt_part_jungkook` 등 7개, 연속 구간으로 근사) | 실제 곡 구간(1절·코러스·브리지)과 맞지 않는다. 같은 구간을 여러 멤버가 부르는 경우를 나타낼 수 없다 |
| 스템 = (슬롯, 부른 멤버) | 한 구간에 목소리가 둘 이상이면 어느 목소리를 바꾸는지 구분할 수 없다 |
| 발행 배정 = 슬롯마다 스템 하나(`snapshot_stem_assignment` PK가 snapshot·slot) | 듀엣·합창 구간은 한 사람만 배정된다 |
| 원곡 담당 멤버는 슬롯 id 이름에만 있다 | 원곡 배치(대각선)를 데이터로 알 수 없다 |

## 새 구조

```
곡 → 녹음 → 슬롯(곡 구간, 시간순) → 보컬 라인(1..n) → 스템(그 라인을 부른 멤버별 녹음)
                                     └ 원곡 담당 멤버(라인마다 1명)
```

- **슬롯** = 곡의 구간 하나. 시작·끝은 원곡 음원의 실제 시각이고, 구간 이름(1절·프리코러스·코러스·브리지·아웃트로 등)과 종류(보컬·랩·반주)를 갖는다
- **보컬 라인** = 그 구간 안의 목소리 하나. 한 명이 부르면 라인 1개, 두 명이 함께 부르면 라인 2개, 7명 합창이면 라인 7개. 라인마다 원곡 담당 멤버와 역할(리드·화음·애드리브·제창)이 있다
- **스템** = 어떤 라인을 누가 부른 녹음 하나. 원곡 담당이 부른 것이 원곡 배치 스템, 다른 멤버가 같은 라인을 부른 것이 추가 녹음 스템이다
- **조합** = 모든 보컬 라인마다 스템 하나를 고른다. 듀엣 구간은 두 라인을 각각 바꿀 수 있다

## DB 변경

| 표 | 변경 |
| --- | --- |
| `part_slot` | 열 추가: `section_label`(구간 이름), `kind`(`VOCAL`·`RAP`·`INSTRUMENTAL`). 시작·끝은 원곡 실제 시각. 기존 순서 유일성 그대로 |
| `slot_lane`(새) | `slot_id`, `lane_no`(1부터), `role`(`LEAD`·`HARMONY`·`ADLIB`·`UNISON`), `original_party_id`(원곡 담당 멤버), `original_voice_id`. PK(slot_id, lane_no). 반주 슬롯은 라인 없음 |
| `stem` | 열 추가: `lane_no`. FK(slot_id, lane_no) → `slot_lane`. 반주(MR) 스템은 라인 없이(NULL) |
| `snapshot_stem_assignment` | 열 추가: `lane_no`. PK를 (snapshot_id, slot_id) → (snapshot_id, slot_id, lane_no)로. 기존 행은 라인 1로 이전 |
| 이전(마이그레이션) | 기존 슬롯마다 라인 1을 만들고, 원곡 담당은 그 슬롯 스템 중 슬롯 이름의 멤버. 기존 스템·배정은 라인 1 |

## 코어 변경

- **발행 검사:** "슬롯 중복 금지"를 "같은 (슬롯, 라인) 중복 금지"로 바꾼다. 보컬 슬롯은 라인을 모두 채워야 한다(빠진 라인은 `LANE_MISSING`). 스템이 그 슬롯·라인의 스템인지 확인한다
- **사용 시간(조합 지분 IR의 입력):** 스템별 사용 시간 = 그 슬롯 길이. 듀엣이면 두 스템이 각각 슬롯 길이를 받는다(함께 부른 시간은 둘 다 부른 시간). 정책의 "부른 시간 60%"는 이 합으로 나뉜다 → 결정 SL2
- **함께 만드는 실연 주장(ID3):** 스템 등록 때 스템 → 부른 멤버의 보이스 주장. 라인과 무관하게 그대로
- **확인 요청:** 원곡 담당 지정(라인)도 멤버 확인 대상에 넣는다 → 결정 SL3
- **팬 채널 API:** 배정을 `{slotId, laneNo, stemId}`로. `laneNo`가 없으면 라인 1(하위 호환)
- **정합성 규칙:** 보컬 라인에 원곡 배치 스템이 없으면 경고, 원곡 담당 멤버의 보이스가 없으면 차단

## MDRL 변경

- 엔진은 계산에 슬롯을 쓰지 않는다(몫은 스템별 사용 시간으로 계산). 그래서 바뀌는 것은 facts 문서의 스템 항목뿐이다
- facts `Stem`에 선택 항목 `lane`(라인 번호 문자열)을 더한다. 검증·텍스트 형식(`stem … { of; slot; lane; rights_bearing; }`)에 반영한다
- 항목이 없으면 지금과 같으므로 **기존 facts digest는 바뀌지 않는다**(라인 1을 굳이 적지 않는다 → 결정 SL4). 정책·조합 지분·멤버 IR 형식은 그대로

## Dynamite 데이터

- 지금 시드는 "멤버별 총 가창 시간"(정국 71,890ms 등)을 멤버마다 연속 구간 하나로 근사했다
- 새 구조에서는 원곡의 실제 구간과 구간별 담당 멤버(함께 부르는 구간 포함)가 필요하다. 공개 자료에서 구간별 담당을 확인하지 못했다(멤버별 총 가창 시간만 있음). 그래서 **빅히트의 원본 크레딧·가사 배분 자료로 입력**해야 한다 → 결정 SL5
- 구간·라인이 바뀌면 사용 시간이 바뀌므로 Dynamite 예시 보고서의 금액(소속사 2,285,920 등)이 달라진다. 새 데이터로 예시 보고서·시험 기대값을 다시 만든다

## 결정 사항

- [ ] **SL1** 한 구간 여러 멤버의 모델 (막는 항목: 전부)
  - 제안: 라인 모델(구간 → 라인 1..n, 라인마다 원곡 담당 1명). 제창도 멤버 수만큼 라인을 둔다. 스템을 라인 단위로 만들면 듀엣의 한쪽만 바꾸는 조합이 된다
- [ ] **SL2** 함께 부른 구간의 사용 시간
  - 제안: 라인마다 슬롯 길이 전체를 준다(나누지 않는다). 필요하면 라인별 비중(`weight_bps`)을 나중에 더한다
- [ ] **SL3** 원곡 담당 지정을 멤버 확인 대상에 넣을지
  - 제안: 넣는다. 라인의 원곡 담당은 그 멤버의 실연 사실이므로 실연 주장과 함께 확인 요청이 간다
- [ ] **SL4** facts에 라인 1을 적을지
  - 제안: 라인이 하나뿐인 슬롯은 적지 않는다(digest 유지). 라인이 둘 이상인 슬롯만 `lane`을 적는다
- [ ] **SL5** Dynamite 구간·담당 데이터의 출처
  - 제안: 빅히트 원본 자료로 입력. 시안·데모는 그때까지 "가정 데이터"로 표시한다

## 진행 단계

- [ ] **SL-S1** 마이그레이션: `part_slot` 열, `slot_lane`, `stem.lane_no`, `snapshot_stem_assignment.lane_no`·PK, 기존 데이터 라인 1 이전 (막는 결정: SL1)
- [ ] **SL-S2** MDRL facts `Stem.lane`(선택) — 검증·텍스트 형식, 기존 digest 불변 시험 (막는 결정: SL4)
- [ ] **SL-S3** 코어: 슬롯·라인 등록·조회·수정 API(IR 생성 전), 스템 라인, 발행 검사(라인별 배정·누락), 사용 시간, 팬 API 하위 호환, 정합성 규칙 2개 (막는 결정: SL2·SL3)
- [ ] **SL-S4** Dynamite 시드를 구간·라인으로 다시 만들고 예시 보고서·시험 기대값 갱신 (막는 결정: SL5)
- [ ] **SL-S5** 화면: 원곡 권리의 실연을 구간·라인 기준으로, 스템 탭을 라인 × 부른 멤버로(시안 v2 갱신)
