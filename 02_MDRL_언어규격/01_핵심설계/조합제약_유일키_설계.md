# 조합 제약·유일키 설계

상태: 설계 확정 (구현 전)
상위: `데이터모델.md`

팬 빌더의 조합은 **비율 규칙만**으로 끝나지 않는다. 멤버 쌍·연속 스템 패턴을 막고, 같은 조합이 두 번 발행되지 않도록 **지문(fingerprint) + 유일 키**로 잠근다.

검증은 빌더에서 실시간, 공식 발행은 `verification_run` + 승인 + 권리 스탬프 이후에만 한다. 통과한 제약 세트·유일 키·스탬프는 스냅샷에 붙는다.

---

## 1. 연속 스템의 정의

할당된 스템만 타임라인 순으로 세운다.

```
order = (start_ms, stem.sort_order, stem_id)
```

인접 = 이 수열에서 인덱스 i와 i+1.

- 미배정(ghost) 칸: 기본은 **건너뛴다** (`skip_unassigned = true`). A · 빈칸 · B 는 인접으로 본다.
- 잠금 스템: 배정이 있으면 수열에 **포함한다**. 잠금이라서 제약을 우회하지 않는다.
- 큐브 모드: 같은 시각에 겹치는 셀은 한 슬롯이 아니라 **레인별 수열**로 검사할 수 있다. 기본은 팩의 `sort_order` 단일 수열.

---

## 2. 제약 타입

`issuance_rule`의 비율 cap(1인 90% 미만 등)과 **별도 테이블**이다. 팩 기본 + 캠페인 오버라이드(추가·강화만, 팩 금지를 캠페인이 풀지는 못 함).

| type | 의미 | 파라미터 |
| --- | --- | --- |
| `FORBIDDEN_CO_OCCURRENCE` | 특정 보컬들이 **한 조합에 함께** 있으면 차단 | `party_ids[]` (2명 이상). 전원 출연 시 실패 |
| `FORBIDDEN_ADJACENT` | **연속 스템**에 지정 두 보컬이 이웃하면 차단 | `party_a`, `party_b`, `directed` |
| `FORBIDDEN_CONSECUTIVE_SWAP` | 같은 두 보컬이 연속 스템에서 **서로 바꿔 끼워진** 패턴 차단 | `party_ids[2]`, `mode` |

### 2.1 동시 조합 불가 (`FORBIDDEN_CO_OCCURRENCE`)

조합에 등장하는 distinct `party_id`가 `party_ids`를 모두 포함하면 BLOCK.

예: 뷔와 지민을 같은 VC에 넣지 못 함. 비율·스템 위치와 무관하다.

### 2.2 연속 인접 금지 (`FORBIDDEN_ADJACENT`)

인접 배정 `(p_i, p_{i+1})`가 `{party_a, party_b}`이면 실패.

- `directed = false`: A→B, B→A 모두 실패.
- `directed = true`: A→B만 실패, B→A는 허용.

### 2.3 연속 스템 교차 조합 금지 (`FORBIDDEN_CONSECUTIVE_SWAP`)

“두 명의 보컬이 연속된 스템에서 **다르게** 조합되는 것”을 이 타입으로 둔다.

`mode`:

- `NO_SWAP` (기본): 한 VC 안에 인접 엣지 A→B와 B→A가 **둘 다** 있으면 실패. 한 방향만 쓰는 진행은 허용.
- `NO_DISTINCT`: 해당 두 명이 인접 스템에 **서로 다른 칸**으로 한 번이라도 있으면 실패. (`FORBIDDEN_ADJACENT` directed=false와 동일, 명시적 별칭)

`party_ids`를 생략하고 `apply_to = ALL_PERFORMER_PAIRS`이면 모든 멤버 쌍에 같은 모드를 적용한다.

---

## 3. 평가 순서

1. 그랜트 (지역·행위·파트·잠금 스템 변경 불가)
2. `issuance_rule` 비율 (합 10000, 1인 cap, 최소 인원·최소 %)
3. `combination_constraint` ACTIVE 전부 (팩 ∪ 캠페인). severity `BLOCK` 하나라도 실패면 발행 거부
4. 유일 키 확보 (아래)
5. 스냅샷 + ISSUED

빌더는 1–3을 배정할 때마다 돌려 실패 제약 ID·메시지를 칸에 표시한다. 4번은 발행 직전(및 선택적 미리보기).

`WARN`은 발행을 막지 않고 고지만 한다. 기본 운영 제약은 `BLOCK`.

---

## 4. 유일 키

동일 조합의 재발행을 막는다. 제목·팬·시각은 키에 넣지 않는다.

### 4.1 지문 (canonical fingerprint)

UTF-8 JSON, 키 정렬, 공백 없음. SHA-256 hex.

```json
{
  "pack_id": "pak_…",
  "mix_mode": "STEM",
  "assignments": [
    { "stem_id": "stm_…", "party_id": "pty_…", "start_ms": 0, "end_ms": 4120 }
  ],
  "members": [
    { "party_id": "pty_…", "pct_bps": 3000 }
  ]
}
```

- `assignments` 정렬: `start_ms`, `stem_id`. 미배정 제외.
- `members` 정렬: `party_id`. 합 10000인 발행값.
- `mix_bus`는 기본 **제외**. 오디오가 버스에 의존하면 `issuance_rule.fingerprint_include_mix_bus = true`.
- `locked` 플래그는 배정 파티가 같으면 지문에 넣지 않음 (잠금은 그랜트 쪽).

캠페인 ID는 지문 문자열이 아니라 **유일 인덱스 스코프**에 둔다. 같은 지문이 캠페인만 다르면 스코프가 `PACK`일 때만 충돌한다.

### 4.2 스코프

`issuance_rule.uniqueness_scope`

| 값 | UNIQUE | 기본 |
| --- | --- | --- |
| `CAMPAIGN` | `(campaign_id, fingerprint_hash)` 활성 키 | **기본.** 같은 캠페인에서 동일 믹스 1개 |
| `PACK` | `(pack_id, fingerprint_hash)` | 캠페인 걸쳐 전역 유일 |
| `FAN_CAMPAIGN` | `(campaign_id, fan_party_id, fingerprint_hash)` | 같은 팬만 중복 금지. 타인 동일 믹스 허용 |

활성 키 = `combination_identity.status IN ('RESERVED','ISSUED')`.

### 4.3 수명

| status | 의미 |
| --- | --- |
| `RESERVED` | 제출(승인 대기)이 해시 점유. `reserved_until` = 승인 만료(기본 72h) |
| `ISSUED` | `vc_id` 연결. VOID 전까지 유지 |
| `RELEASED` | VOID·거절·만료·발행 실패. 인덱스에서 제외 |

제출 트랜잭션: 제약 통과 → `RESERVED` insert → verification_run PASS 기록 → issue_request. 즉시 AUTO 승인이면 같은 트랜잭션에서 스탬프+ISSUED. 수동 승인이면 PENDING. 충돌 시 `IDENTITY_COLLISION`.

초안 저장은 키를 점유하지 않는다. 미리보기 API는 해시만 계산해 “이미 존재함”을 알려 준다.

---

## 5. 메시지

제약 실패는 코드로 내려 빌더가 칸을 칠한다.

- `CONSTRAINT_CO_OCCURRENCE`
- `CONSTRAINT_ADJACENT`
- `CONSTRAINT_CONSECUTIVE_SWAP`
- `IDENTITY_COLLISION` (+ 스코프. 타인 VC 식별자는 팬에게 노출하지 않음)

---

## 6. 레이블 운영

SPACE/레이블 콘솔: 팩·캠페인별 제약 CRUD, 시뮬(배정 시퀀스 붙여 넣기), 유일 스코프 설정.

이미 ISSUED된 VC는 제약 변경의 영향을 받지 않는다. 새 발행만 새 제약 세트를 쓴다. 유일 키 스코프를 `CAMPAIGN`→`PACK`으로 좁히면 과거 캠페인 간 동일 해시가 있어도 소급 삭제하지 않고, **이후 발행분**부터 PACK 인덱스로 막는다. 충돌 가능 건수는 활성화 전 시뮬로 보여 준다.
