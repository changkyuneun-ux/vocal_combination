# 정책 게이팅 엔진 기술문서 (초안)

상태: 초안
상위: `라이선스_정산_모니터링_백오피스_개념설계.md`, `검증_승인_권리스탬프_설계.md`, `데이터모델.md`

조합·프리뷰·발행·재생·배포·재판매 요청마다 **“지금 이 맥락에서 이 행위가 허용되는가”**를 한 곳에서 판단한다. 허용 범위는 그랜트·캠페인·스탬프에 이미 선언되어 있고, 엔진은 그 선언을 **병합**한 뒤 **자동 검출한 컨텍스트**와 대조한다.

빌더 실시간 힌트, `verification_run`의 GRANT_* 체크, 재생 서버, 배포 파이프라인이 **같은 엔진**을 호출한다. 규칙을 두 번 구현하지 않는다.

---

## 1. 결정 모델

```
Decision = PERMIT | PERMIT_WITH_OBLIGATION | DENY
```

- `PERMIT_WITH_OBLIGATION`: 허용하되 호출자가 **반드시** 수행할 의무가 붙는다. 의무를 못 지키면 호출자는 DENY로 취급한다.
- 결과에는 항상 `reason_codes[]`가 붙는다. DENY는 최소 1개.

### 입력

| 필드 | 내용 |
| --- | --- |
| `subject` | `party_id`, `user_id`, 멤버십 등급, 연령대 |
| `resource` | `pack_id` / `stem_id` / `vc_id` / `stamp_id` (+ 버전) |
| `action` | `PREVIEW \| COMBINE \| ISSUE \| PLAY \| SHARE_LINK \| PLATFORM_DISTRIBUTE \| RESALE \| DOWNLOAD \| COMMERCIAL` |
| `context` | 2절. 자동 검출 결과 |
| `evaluated_at` | 호출자가 넘기는 판단 시각. 엔진 내부에서 `now()`를 읽지 않는다 |

`action`은 `grant_action`과 같은 어휘를 쓴다. `ISSUE`는 스탬프 조항 발행가능(`stamp_eligibility_rule`)으로 내려간다.

### 결정성

같은 (입력, 정책 버전, 그래프 버전) → 같은 출력. 시간·난수·외부 IO를 엔진 안에서 읽지 않는다. 그래야 캐시·리플레이·감사 재현이 성립한다.

## 2. 허용 범위 메타데이터

### 2.1 스코프 서술자 (ScopeDescriptor)

여러 출처의 선언을 하나의 정규 구조로 모은다.

```json
{
  "actions":    { "PREVIEW": true, "PLAY": true, "PLATFORM_DISTRIBUTE": false, "DOWNLOAD": false },
  "territories":["KR", "JP"],
  "parts":      { "allow": ["stm_…"], "deny": ["stm_…"] },
  "window":     { "from": "2026-05-01T00:00:00Z", "to": "2026-05-31T23:59:59Z" },
  "quantity":   { "max_uses": 1, "consumed": 0 },
  "audience":   { "require_membership": "FANCLUB", "min_age": null },
  "obligations":["STREAM_ONLY", "WATERMARK_SESSION"]
}
```

### 2.2 출처와 병합

| 우선 | 출처 | 역할 |
| --- | --- | --- |
| 1 | `license_grant` (+ `grant_action`, `grant_territory`, `grant_part_scope`) | 최대 허용 범위 |
| 2 | `campaign` / `stamp_eligibility_rule` | 좁히기 |
| 3 | `rights_stamp_clause` (ISSUED 자산) | 그 VC의 실제 권리 |
| 4 | 상품·운영 플래그 (예: 지역 긴급 차단) | 좁히기 |

병합 규칙은 **단조 축소(monotonic narrowing)** 하나뿐이다.

```
effective = grant ∩ campaign ∩ stamp ∩ ops
```

- `actions`: **deny-overrides.** 한 층이라도 false면 false.
- `territories`, `parts.allow`: 교집합. `parts.deny`는 합집합.
- `window`: 늦은 시작, 이른 종료.
- `quantity`: 최솟값.
- `obligations`: **합집합.** 의무는 줄어들지 않는다.

하위 층이 상위가 거부한 것을 켜면 **로드 단계에서 거부**한다(`SCOPE_WIDENING_REJECTED`). 런타임에 조용히 무시하지 않는다.

### 2.3 선행 조건 (자산 상태)

그랜트가 `RESTRICTED | EXPIRED | REVOKED | DISPUTE_HOLD`, 스탬프가 `REVOKED | EXPIRED`, 조항이 `EXHAUSTED`면 병합 전에 즉시 DENY. 사유 코드로 구분한다.

## 3. 컨텍스트 자동 검출

### 3.1 신호

| 신호 | 출처 | 주 용도 |
| --- | --- | --- |
| `region_effective` | IP 지오 + 계정 등록국 + 결제국 | 영토 |
| `surface` | 앱(iOS/Android) / 웹 / 임베드 / 서버-투-서버 | 배포·다운로드 |
| `membership` | 팬클럽 구독 상태 | audience |
| `output_path` | 내부 플레이어 / 외부 캐스팅 / 화면 녹화 플래그 | STREAM_ONLY 의무 |
| `client_integrity` | 앱 어테스테이션, 루팅·에뮬레이터 | 민감 액션 |
| `asset_state` | 스탬프 조항 상태·잔여 횟수 | quantity |
| `clock` | 호출자 `evaluated_at` | window |
| `automation` | 봇·스크립트 판정 | 남용 |

### 3.2 신뢰 등급

| 등급 | 뜻 | 예 |
| --- | --- | --- |
| `ASSERTED` | 클라이언트 주장 | 헤더의 국가 코드 |
| `DERIVED` | 서버 추론 | IP 지오, UA 파싱 |
| `VERIFIED` | 신뢰 소스 | 결제 수단 국가, 계정 KYC, 앱 어테스테이션 |

액션별 최소 등급을 정책으로 둔다.

| action | 최소 등급 |
| --- | --- |
| `PREVIEW`, `COMBINE` | `DERIVED` |
| `PLAY`, `SHARE_LINK` | `DERIVED` |
| `ISSUE`, `PLATFORM_DISTRIBUTE` | `VERIFIED` |
| `RESALE`, `DOWNLOAD`, `COMMERCIAL` | `VERIFIED` |

### 3.3 검출 실패

**Fail-closed가 기본**이다. 필요한 신호가 없거나 등급이 모자라면 DENY(`GATE_CONTEXT_UNVERIFIED`).

예외는 하나. `PREVIEW`는 DENY 대신 **격하 허용**할 수 있다. `PERMIT_WITH_OBLIGATION` + `MAX_QUALITY`, `CLIP_ONLY`. 격하 여부는 캠페인 플래그이며 기본 꺼짐.

신호 충돌(예: IP는 JP, 결제는 KR)은 **더 제한적인 쪽**을 쓰고 `GATE_SIGNAL_CONFLICT`를 사유에 남긴다.

## 4. 평가 파이프라인

```
1. 정규화      입력 스키마 검증, action 어휘 매핑
2. 자산 상태   grant/stamp/clause 상태 선검사
3. 스코프 해석 4개 층 로드 → 단조 축소 병합 → scope_digest
4. 컨텍스트    신호 수집 → 등급 판정 → context_digest
5. 대조        actions → territory → parts → window → quantity → audience
6. 의무 산출   obligations 합집합 + 격하 의무
7. 캐시·로그   결정 저장, 지표 기록
```

5단계는 **순서 무관**하다(모든 조건이 AND). 순서는 사유 코드 우선순위를 안정화하기 위한 것일 뿐이다.

### 의무 목록

| obligation | 호출자 책임 |
| --- | --- |
| `STREAM_ONLY` | 파일 핸들·캐시 파일 미제공 |
| `WATERMARK_SESSION` | 세션 워터마크 삽입 |
| `MAX_QUALITY:<kbps>` | 지정 품질 이하 |
| `CLIP_ONLY:<sec>` | 구간 제한 |
| `SESSION_TTL:<sec>` | 토큰 만료 |
| `CONSUME_USE` | 성공 시 `rights_stamp_clause.uses_consumed` 증가 |
| `REQUIRE_REAUTH` | 재인증 후 재요청 |

`CONSUME_USE`는 **호출자가 행위 성공 후** 소비 API를 호출한다. 게이트가 직접 차감하지 않는다(판정과 부작용 분리). 소비 API는 멱등 키를 받는다.

## 5. 사유 코드

```
GATE_GRANT_STATE         GATE_STAMP_STATE        GATE_CLAUSE_EXHAUSTED
GATE_ACTION_NOT_GRANTED  GATE_TERRITORY_MISMATCH GATE_PART_NOT_ALLOWED
GATE_WINDOW_CLOSED       GATE_QUANTITY_EXCEEDED  GATE_MEMBERSHIP_REQUIRED
GATE_CONTEXT_UNVERIFIED  GATE_SIGNAL_CONFLICT    GATE_INTEGRITY_FAILED
SCOPE_WIDENING_REJECTED
```

팬 화면에는 코드별 한 줄 문구를 매핑한다. 타인 `vc_id`·계약 수치는 노출하지 않는다.

## 6. API 스케치

```
POST /gate/evaluate        단건. 응답: decision, reason_codes, obligations, ttl_sec, digests
POST /gate/evaluate:batch  빌더 그리드용 다건(스템 단위). 부분 실패 허용
POST /gate/explain         백오피스 전용. 층별 병합 추적과 탈락 조건
POST /gate/consume         CONSUME_USE 소비. idempotency_key 필수
```

`evaluate`는 읽기 전용이다. 쓰기는 `consume`뿐이다.

---

## 7. 캐시

- 키: `hash(subject_class, resource_version, action, context_bucket)`
- `context_bucket`: 영토·서페이스·멤버십 등 **저카디널리티** 축만. 정밀 IP는 키에 넣지 않는다.
- TTL: `min(정책 TTL, 다음 만료까지 남은 시간)`. `valid_to`·`SESSION_TTL` 경계를 넘기지 않는다.
- 무효화: 그랜트/캠페인/스탬프/운영 플래그 변경 이벤트 → 해당 `pack_id` 접두 무효화.
- `quantity`가 걸린 결정은 **캐시하지 않는다**(잔여 횟수는 실시간).

## 8. 결정 로그

`gate_decision`

| 컬럼 | 내용 |
| --- | --- |
| `decision_id`, `at` | |
| `subject_party_id`, `resource_type`, `resource_id`, `action` | |
| `decision`, `reason_codes[]`, `obligations[]` | |
| `scope_digest`, `context_digest` | 재현 키 |
| `signals_json` | 등급 포함. 원시 IP는 저장하지 않고 지역·해시만 |
| `latency_ms` | |

저장 정책: `DENY`와 `PERMIT_WITH_OBLIGATION`은 **전량**, `PERMIT`은 샘플링 + 분당 집계. 분쟁·침해 조사에 쓰이므로 보존 기간은 감사 로그와 맞춘다.

## 9. 실패 모드

| 상황 | 동작 |
| --- | --- |
| 정책 저장소 장애 | 최근 스코프 캐시로 `PREVIEW`/`PLAY`만 제한 허용, 민감 액션 DENY |
| 컨텍스트 서비스 지연 | 타임아웃 후 등급 강등 → fail-closed |
| 스코프 병합 모순 | `SCOPE_WIDENING_REJECTED`, 운영 알림 |
| 캐시 불일치 의심 | `explain`으로 실시간 재평가 |

---

## 10. 관측 지표

- 액션별 DENY율, 사유 코드 분포
- `GATE_CONTEXT_UNVERIFIED` 비율 (검출 품질)
- p95 평가 지연, 캐시 적중률
- 빌더 실시간 판정과 `verification_run` 결과 **불일치 건수** (0이어야 정상)

마지막 지표가 이 엔진의 존재 이유다. 빌더에서 통과한 조합이 발행에서 떨어지면 구현이 갈라진 것이다.

---

## 11. 미결

- 오프라인 재생 허용 시 토큰 수명과 `CONSUME_USE` 정합
- VPN·프록시 판정 수준 (민감 액션 차단까지 갈지)
- 미성년 보호 규칙을 `audience`에 넣을지 별도 층으로 둘지
- `explain` 결과를 레이블 포털에 어디까지 열지
