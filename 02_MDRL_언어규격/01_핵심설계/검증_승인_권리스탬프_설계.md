# 발행 전 검증·승인·권리 스탬프 설계

상태: 설계 확정 (구현 전)
상위: `데이터모델.md`, `조합제약_유일키_설계.md`

공식 발행은 초안 저장과 다르다. **시스템 검증 기록 → 승인 → 권리 스탬프 발행**이 끝난 뒤에만 VC가 `ISSUED`가 된다. 스탬프는 그 조합이 실제로 쓸 수 있는 최종 권리(개인 소장, 플랫폼 배포, 한정 이용)의 공적 증명이다.

---

## 1. 상태 흐름

```
DRAFT → (제출) → SUBMITTED
                 ├ verification FAIL → DRAFT (수정)
                 ├ verification PASS + 요청 스탬프 전부 AUTO → ISSUED
                 └ verification PASS + 수동 승인 필요 → 승인 대기
                      ├ APPROVE → ISSUED
                      └ REJECT / 만료 → DRAFT, 유일키 RELEASED
ISSUED → VOID (스탬프 REVOKED, 유일키 RELEASED)
```

`vocal_combination.status`: `DRAFT | SUBMITTED | ISSUED | VOID`.

검증 결과·승인 결과는 자식 테이블에 남긴다. VC 상태만으로  fort 이력을 덮어쓰지 않는다.

---

## 2. 시스템 검증 (`verification_run`)

제출 시 한 번 생성. 빌더 실시간 힌트와 **같은 규칙**이지만, 발행용은 이 런 ID가 스냅샷에 붙는다.

| check_code | 내용 |
| --- | --- |
| `GRANT_TERRITORY` | 이용 지역 |
| `GRANT_ACTION` | 요청 스탬프 유형이 그랜트 행위와 맞는지 |
| `GRANT_PART` | 잠금·비허용 스템 |
| `ISSUANCE_RATIO` | 합 10000, 1인 cap, 최소 인원/% |
| `CONSTRAINT` | 동시출연·연속 스템 등 |
| `UNIQUENESS` | 조합 구성 해시 충돌 여부 (점유 전 조회 + 점유) |
| `STAMP_ELIGIBILITY` | 요청한 조항이 당시 발행가능 집합에 있는지 |
| `RENDER_INTEGRITY` | 선택. 렌더 해시와 배정 일치 |

런 `result`: `PASS | FAIL`. 하나라도 BLOCK 실패면 FAIL. WARN은 PASS로 두되 체크 행에 남긴다.

`eligible_clauses_json`: 검증 시점에 계산한 **발행가능 스탬프 조항** 스냅샷. 승인자는 이 집합의 부분집합만 확정할 수 있다. 검증 이후 그랜트가 바뀌어도 이 런은 재사용하지 않고 재제출한다.

---

## 3. 스탬프 조항과 발행가능

그랜트/캠페인이 “무엇을 찍을 수 있는지”를 정의하고, 승인이 “이번에 무엇을 찍을지”를 고른다.

| clause_type | 의미 | 기본 승인 |
| --- | --- | --- |
| `PERSONAL_HOLD` | 개인 소장. 앱 내 본인 재생·보관. 외부 유통 아님 | AUTO |
| `PLATFORM_DISTRIBUTE` | 플랫폼 피드·캠페인·추천 등 **플랫폼 안** 배포 | SPACE 또는 LABEL |
| `LIMITED_USE` | 한정 이용. 아래 limit_kind와 함께 | 템플릿에 따름 |

`LIMITED_USE.limit_kind`:

| kind | 파라미터 | 예 |
| --- | --- | --- |
| `TIME_BOUND` | `valid_from`, `valid_to` | 컴백 주간만 |
| `ONE_SHOT` | `max_uses = 1` | 1회 재생 또는 1회 공유 후 소진 |
| `COUNT` | `max_uses = n`, `uses_consumed` | n회 |
| `CAMPAIGN_WINDOW` | 캠페인 `starts_at`/`ends_at` 상속 | 이벤트 기간 |

조항은 한 스탬프에 **여러 개** 붙을 수 있다. 예: 개인 소장 + 기간 한정, 개인 소장 + 플랫폼 배포(기간 한정).

`PLATFORM_DISTRIBUTE`는 `SHARE_LINK`(팬이 링크 복사)와 다르다. 배포는 플랫폼이 표면을 고르는 권리이다.

### 3.1 발행가능 규칙 (`stamp_eligibility_rule`)

팩 기본, 캠페인·그랜트가 덮어쓸 수 있다. **좁히는 것만** 허용 (그랜트가 거부한 조항을 캠페인이 켜지 못 함).

| 컬럼 | 내용 |
| --- | --- |
| clause_type | 위 ENUM |
| issuable | 이 맥락에서 찍을 수 있는지 |
| approval_mode | `AUTO \| LABEL \| SPACE` |
| allowed_limit_kinds | LIMITED_USE일 때 허용 kind 배열 |
| default_limit_json | 제출 시 기본값 |
| max_valid_days | TIME_BOUND 상한 |

검증 `STAMP_ELIGIBILITY`: 요청 조항 ⊆ 그랜트 행위 ∩ 캠페인 룰 ∩ issuable=true.

그랜트 매핑:

- `PERSONAL_HOLD` ← `grant_action.PERSONAL_HOLD`
- `PLATFORM_DISTRIBUTE` ← `grant_action.PLATFORM_DISTRIBUTE` (신규. 기본 거부 또는 캠페인만 true)
- `LIMITED_USE` ← 그랜트/캠페인 한정 템플릿이 하나라도 있을 때. 단독 상업유통 아님

COMMERCIAL/DOWNLOAD는 스탬프 조항이 아니다. 기본 불가.

## 4. 승인 (`issue_request`)

제출 시 생성. `verification_run_id` 필수.

| 컬럼 | 내용 |
| --- | --- |
| requested_clauses | 팬이 고른 조항 (eligible의 부분집합) |
| required_approval_mode | 요청 조항 중 가장 높은 모드 (AUTO < LABEL < SPACE) |
| status | `PENDING \| APPROVED \| REJECTED \| EXPIRED` |
| expires_at | 기본 72시간 |
| decided_by, decided_at, reason | |

- 모든 요청 조항이 `AUTO`이고 검증 PASS → 같은 트랜잭션에서 즉시 APPROVED.
- 하나라도 LABEL/SPACE → `PENDING`. 해당 포털 큐.
- 승인자는 eligible에 없는 조항을 추가하지 못 함. 조항을 **줄이는** 것만 가능 (예: 배포 요청을 반려하고 소장만 승인).
- 거절/만료: VC `DRAFT`, identity `RELEASED`.

유일키: 제출 때 `RESERVED`, `reserved_until = expires_at`. 승인 완료 시 `ISSUED`.

---

## 5. 권리 스탬프 (`rights_stamp`)

승인 확정과 공식 발행이 **같은 트랜잭션**이다. 스탬프 없이 `ISSUED` 금지.

| 헤더 | 내용 |
| --- | --- |
| stamp_id | `stp_` |
| vc_id | 활성 스탬프 1개 (UNIQUE where status=ACTIVE) |
| snapshot_id, verification_run_id, issue_request_id | |
| fingerprint_hash | 조합 구성 해시 |
| status | `ACTIVE \| REVOKED \| EXPIRED` |
| issued_at | |

### 조항 행 (`rights_stamp_clause`)

| 컬럼 | 내용 |
| --- | --- |
| clause_type | PERSONAL_HOLD / PLATFORM_DISTRIBUTE / LIMITED_USE |
| limit_kind | LIMITED_USE만 |
| valid_from, valid_to | |
| max_uses, uses_consumed | ONE_SHOT/COUNT |
| status | `ACTIVE \| EXHAUSTED \| EXPIRED` |

만료: TIME_BOUND/CAMPAIGN_WINDOW는 `valid_to` 경과 시 조항 EXPIRED. 전 조항이 죽어도 헤더를 즉시 REVOKED하지는 않는다. 소장 조항이 남아 있으면 재생은 유지. 배포 조항만 만료되면 플랫폼 노출을 내린다.

ONE_SHOT/COUNT 소진은 재생·배포 이벤트에서 `uses_consumed`를 올린다. 스탬프 헤더와 조항은 UPDATE가 허용되는 예외(소진 카운트, 상태 전이). 조항 **내용**(기간, 유형)은 UPDATE 금지. 기간 연장은 새 승인+새 스탬프(기존 REVOKED).

VOID: 헤더 REVOKED.

팬·권리자 화면에 스탬프 ID, 조항, 만료를 보여 준다. 이것이 목업의 “권리 스냅샷” 고지를 대체하는 공식 객체다.

---

## 6. 발행 트랜잭션 (최종)

1. 검증 PASS인 `verification_run` (요청 조항과 조합 구성 해시가 현재 초안과 일치)
2. `issue_request` APPROVED (AUTO면 이 트랜잭션에서 승인)
3. 유일키 활성 RESERVED → ISSUED
4. rights_snapshot + 권리 스탬프·조항 insert
5. vc `ISSUED`, ledger ISSUE

불일치(제출 후 초안 수정)면 재검증. SUBMITTED 중 배정 변경은 요청을 무효화한다.

---

## 7. 운영 화면

- **팬:** 검증 체크리스트, 발행가능 조항만 선택, 승인 대기 상태, 스탬프 보기.
- **레이블:** LABEL 모드 큐. 배포 조항 축소 승인.
- **SPACE:** SPACE 모드 큐, 스탬프 폐기, 만료 모니터.
- 감사: verification_check, 승인 결정, 스탬프 조항, 소진 이벤트를 audit_log에 남긴다.

---

## 8. 정산과의 관계

스탬프 조항이 바뀐다고 과거 거래 배분율을 바꾸지 않는다. `PLATFORM_DISTRIBUTE`가 있는 ISSUED만 캠페인 노출·1차 소장 구매 대상이 될 수 있는지는 상품 정책으로 `settlement_rule`과 별도 플래그 `requires_distribute_clause`를 둘 수 있다. 기본: 개인 소장만 찍힌 VC도 본인 구매(소장권) 정산 대상. 플랫폼 노출 과금은 배포 조항이 ACTIVE일 때만.
