## 1. 설계 원칙 (UI 관점)

| 원칙 | UI에서의 의미 |
|---|---|
| **슬롯 ≠ 스템** | 슬롯(구간)은 곡 구조 편집기에서 만들고, 스템(파일)은 슬롯 × 멤버 셀에 업로드한다. 화면의 기본 뷰는 **슬롯 × 멤버 매트릭스**다. |
| **2계층만 존재** | 화면 계층은 `원본 권리 이미지 → 팩` 두 단계. 채널/캠페인/에디션 메뉴는 팩 상세의 탭으로 흡수한다. 팩 아래에 하위 캠페인을 만드는 UI는 없다. |
| **차분만 입력** | 팩 화면의 모든 규칙 필드는 기본이 "원본 상속". 사용자가 "직접 설정"으로 전환한 값만 저장된다. 상속 값은 회색, 직접 설정 값은 진하게 표시한다. |
| **축소 전용 계승** | 팩 필드마다 원본의 상한/하한을 배지로 표시하고, 범위 밖 입력은 저장 전에 인라인 오류(`INHERITANCE_VIOLATION`)로 막는다. |
| **평탄화 결과 노출** | 팩 상세에 "유효 정책 미리보기" 탭을 두어 원본 ⊕ 차분의 평탄화 결과(빌더·검증·정산이 실제로 읽는 값)를 항상 확인할 수 있게 한다. |
| **복제로 반복** | 시즌/이벤트 반복은 "팩 복제" 액션으로 처리한다. 복제 후 기간/이름/조건 재입력 화면으로 바로 진입한다. |
| **하드 전파 가시화** | 동의 철회·킬 스위치·원본 REVOKED는 팩 목록/상세에 즉시 경고 배너로 표시한다(핀 고정과 무관). |
| **L0 = 권리 원장 + 기본 정책** | 원본 이미지 화면은 [템플릿] [권리 원장(파티별 역할·동의·개인 상한·기본 지분)] [이용 정책 기본값·상한] [정산 정책 기본값·하한] [기본 제약] [버전] [파생 팩]. 팩 화면의 정책 탭은 원본 값(회색)/차분(진하게)으로 1:1 대응한다. 총량 상한은 원장 합집합으로 자동 계산되므로 수기 입력 UI를 두지 않는다. |
| **이용 정책 ≠ 정산 정책** | 같은 계승 메커니즘을 쓰는 서로 다른 버전 객체다. 팩 화면에서 [이용 정책(기획사 설정 → 마스터 권리자 그랜트 승인)]과 [정산 정책(마스터 권리자 편집 → 저작권자·기획사 승인)]을 별도 탭·별도 상태 배지·별도 승인 버튼으로 분리한다. 탭 헤더에 정책 ID/버전/상태/편집 주체/승인 주체/활성화 주체를 항상 표시한다. |
| **정산 주체는 party만** | 테넌트·그룹 party는 금액 화면에 수취인으로 나타나지 않는다. 청구권자 목록은 수기 입력이 아니라 원천(마스터 권리자/저작자 크레딧/스템 크레딧/기획사/AI/녹음 크레딧)에서 **도출된 목록 + 권리자 추가**로 표시하고, 버킷 표에는 `member_source`와 커버리지 결과를 항상 함께 보여준다. 스템이 없는 권리자(저작자·CMO·마스터 권리자·기획사·녹음 참여자)의 몫은 조합 내용과 무관함을 화면 문구로 명시한다. |
| **플랫폼 = 검증자·집행자** | 권리 판단(슬롯/크레딧 확정, 허용 범위, 발행 요청 승인, 권리 침해 신고 판정, 활성화)은 권리자 콘솔에만 둔다. 플랫폼 운영 백오피스에는 무결성 예외 처리, 검증 리포트(PASS/FAIL), 플랫폼 정책 검토(약관/법규/이상거래), 정산 집행, 감사만 둔다. 운영자 화면에는 승인/반려/활성화 버튼이 없고, 테넌트가 위임한 업무만 "대행" 배지와 함께 노출된다. |
| **두 관문의 무결성** | 스템 등록(유입)과 스탬프 외부 반출(유출)은 유통사와 같은 관문이다. KYB 미완료 테넌트는 스템 READY·팩 LIVE 버튼이 비활성화되고 사유 배너가 뜬다. 스템 셀에는 QC와 별도로 **무결성 배지**를 둔다. 부정 이용 판정은 플랫폼 정책 판단이므로 플랫폼 화면(5.3)에 두고, 권리자에게는 결과·보류·역분개 금액만 보여준다. |
| **동의 계층** | 동의 화면은 C1~C7 목록이 아니라 **파티 × 단계(T0/T1/T2)** 매트릭스로 보여준다. 하위 단계는 상위 동의 범위를 좁힐 수만 있고, AUTO 셀은 상위 동의에서 자동 파생됨을 배지로 표시한다. 팩 게이트가 막히면 "누가·어느 단계·어떤 유형·등급 부족"을 한 줄 사유로 보여준다. 실연자는 T0 서명과 T1 확인 두 번만 하고 팩은 알림만 받는다. |

## 4. Userflow 변경 지시

### Flow 0(신규) 테넌트 온보딩 확인(KYB)
1. 플랫폼: 테넌트 개설 → `KYB_BASIC`(사업자 진위) 확인 시 초안 작성 권한 부여.
2. 권리자: 대표자·실소유자 증빙 제출 → 플랫폼: 제재 명단·외부 공유 차단 목록(IN) 대조 → `KYB_FULL`.
3. `KYB_FULL` 전에는 스템 READY·원본 이미지 ACTIVE·팩 LIVE 불가(`KYB_REQUIRED`). 연 1회 재확인, 만료 시 신규 팩 LIVE만 차단(기존 LIVE 팩 유지).
4. 신규 테넌트·신규 파티의 초기 지급은 `release_after`(기본 30일)까지 보류.

### Flow 1(소스 등록 & QC/라벨링) — 재정의
1. 마스터 권리자: 곡(ISWC)·저작자 크레딧, 녹음 버전(ISRC/BPM/Key)·녹음 크레딧 등록.
2. 마스터 권리자 작성 → 기획사 확인: **곡 구조 편집기**에서 슬롯 생성(섹션/레이어/타임코드/순서/`swappable`). 시스템이 겹침/공백/길이 정합을 자동 검증(실패 시 저장 불가).
3. 마스터 권리자: **슬롯 × 멤버 매트릭스**에서 각 셀에 스템 파일 업로드(테이크 버전), 셀 단위 가창 크레딧 입력. `rights_bearing=FALSE` 슬롯(MR/FX)은 멤버 열 없이 단일 셀.
4. 시스템: 스템 파일 단위 자동 QC(포맷/클리핑/무음/라우드니스/해시) + **소스 무결성 검사**(상용 음원 핑거프린트·AI 생성·음성 유사도·메타데이터). 무결성 REVIEW/BLOCK은 권리자에게 소명 요청, 플랫폼 3.3 큐는 증빙 확인만. 실패 건만 Ops 무결성 예외 큐(재검토/재업로드 요청, 기술 판정만). 슬롯 매핑·크레딧·동의(C3/C4) 완비 시 셀 상태 `READY` 자동 전이.
5. 시스템: 녹음의 READY 스템으로 **원본 권리 이미지 초안** 자동 생성 제안(Flow 1-A로 연결).

### Flow 1-A(신규) 원본 권리 이미지 확정/개정
1. 시스템: 권리 사실에서 **권리 원장** 초안 자동 도출(마스터 권리자/저작자·CMO/가창자/기획사/AI 원천/정산 참여 녹음 크레딧), 각 행의 개인 상한을 연결 동의 범위에서 채움. 마스터 권리자(마스터·저작권 행)·기획사(멤버·퍼블리시티 행)가 확인·보정, 실연자는 동의 서명. 총량 상한은 합집합 자동 계산.
1-b. 마스터 권리자 + 기획사: **이용 정책 기본값·상한** 입력(기본 지역/행위/조항·승인 모드, 발행 룰 기본값·범위, party 상한 초과 처리 모드). 마스터 권리자: **정산 정책 기본값·하한** 입력(플랫폼 계약 구간 내 Tier 1 기본값, 버킷 기본값·멤버 원천, 실연 풀 기본 모드, 가격 구간) → 저작권자 저작권 버킷 승인.
2. 기획사: 필수 잠금 슬롯(`required_locked`), 기본 선택, 기본 조합 제약(`owner_type=IMAGE`) 설정 및 승인.
3. Ops/Legal: 이미지 검증 리포트(템플릿 완비·베이스라인 정합) PASS → 기획사(없으면 마스터 권리자)가 `ACTIVE` 확정.
4. 개정: 슬롯/스템/크레딧/베이스라인 변경 시 "새 버전 생성" 다이얼로그 → diff 표시 → 파생 팩 목록에 `stale` 배너. 동의 철회·킬 스위치는 버전 생성 없이 즉시 전파.

### Flow 2(Consent Vault) — **동의 계층 T0 → T1 → T2로 재정의**
1. **T0 원천**: 마스터 권리자가 녹음 등록 후 원천 권리자 전원에게 동의 요청 — 저작자/신탁단체(작품 원천), 마스터(자기 서명), 가창자(실연 원천, 주실연은 기획사 연서 → 본인 서명, 미성년 법정대리), AI 원천. 가창자는 **등급(G1/G2/G3)** 과 변형·지역·기간을 선택해 서명. 전원 SIGNED 시 원본 이미지 초안 생성 가능.
2. **T1 조합(1차 이미지)**: 이미지 초안 확정 시 시스템이 T0 범위로 파티별 개인 상한을 채움 → 마스터 이미지 확정 승인, 기획사 퍼블리시티 기본 서명, 주실연자·AI 원천 개인 상한 확인(축소만), 저작자·신탁단체·부실연자는 AUTO(범위 밖 변형이 있으면 저작자 EXPLICIT). 요구 매트릭스 T1 충족 시 이미지 ACTIVE.
3. **T2 팩(2차 이미지)**: 팩 설정 → 그랜트가 각 파티 T1 상한·등급 안인지 계승 검증(`CONSENT_GRADE_INSUFFICIENT`·`CONSENT_SCOPE_EXCEEDED`) → 마스터 그랜트 승인, 기획사 팩 퍼블리시티·활성화, 저작권 버킷 변경 시 정산 승인, AI 원천 팩 확인 서명. 실연자는 AUTO(알림만). 요구 매트릭스 T2 전 역할 충족 시 팩 APPROVED.
4. **재동의·철회**: 약관 중대 개정, 이미지 개정(영향 파티만), 만료 30일 전 재동의 요청. T0 철회는 모든 이미지·팩, T1 상한 축소는 해당 이미지 파생 팩 재검증, T2 이의는 그 팩에서만 제외로 전파.

### Flow 3(조합 룰·안분 정책) + Flow 4(캠페인) — **하나의 "팩 이미지 생성·활성화" 플로우로 통합**
1. 기획사: 팩 생성(원본 이미지 버전 선택·핀) 또는 **기존 팩 복제** → 기본 정보(채널·에디션·기간·가격·수량·유일 스코프) 입력.
2. 기획사: 스템 범위 탭에서 제외/추가 잠금 설정(차분). 원본 필수 잠금은 잠긴 상태로 표시.
3. 기획사: **이용 정책** 새 버전 — 그랜트(지역/행위/파트: 총량 상한·party 개인 상한 내, 초과 party는 EXCLUDE_PARTY 경고와 함께 자동 제외), 조합 룰(발행 비율, 추가 제약), 스탬프 조항 → 마스터 권리자 그랜트 승인.
4. 마스터 권리자: **정산 정책** 새 버전 — Tier 1(계약 구간·하한 배지), 버킷·멤버 원천, 실연 풀 모드 → 저작권자(저작권 버킷)·기획사 승인. 청구권자 탭에서 원장 도출 결과·커버리지 확인.
5. 시스템: 저장 시마다 **계승 검증** 실행, 위반 필드 인라인 표시. 유효 정책 미리보기 갱신.
6. 승인: 마스터 권리자(수량/가격·그랜트) → 저작권자(저작권 풀) → Ops 검증 리포트(계승·배분율·커버리지 가드·동의 커버리지) → Legal 검증 확정.
7. 기획사(편집자와 다른 계정): 두 정책이 모두 `APPROVED` 이상일 때 팩 `APPROVED` 확정 → 오픈 일시에 `LIVE`. 정책 변경은 각 정책의 새 버전, 팩은 `pack_version` 증가.

### Flow 4-A(신규) 팩 복제
1. 팩 목록/상세에서 "복제" → 다이얼로그: 원본 이미지 버전(동일 유지 / 최신으로 마이그레이션), 복사 범위 확인.
2. 복제본 `DRAFT` 생성 → 기본 정보 재입력 화면(이름·기간 필수) → 계승 검증 → 승인 절차 재진행.

### Flow 5(발행 요청 승인 & 신고 검토) — 재정의
1. 팬 조합이 검증 엔진 통과 → 개인 보유 조항 자동 발행. 팩 사전 승인 범위 내 배포/상업/다운로드 조항도 자동 부여.
2. 범위 밖 조항 요청만 **기획사 발행 요청 승인 큐**(72h, 축소 승인 가능, 미응답 시 VOID). 플랫폼 에스컬레이션 없음. 테넌트가 위임한 경우에만 Ops "대행 업무함"에 노출.
3. 공개/랭킹/외부 공유 조합 신고 접수 → 시스템/Ops가 **사유 분류**(권리 침해·브랜드 vs 약관·법규·이상거래). Ops는 분류만 하고 판단하지 않음.
4. 권리 사유 → **권리자 콘솔 권리 검토 큐**(기획사/마스터 권리자 판정 HIDDEN/RESTORED, SLA 24h). 플랫폼 정책 사유 → **Ops 플랫폼 정책 검토 큐**(판정/집행, SLA 24h).
5. 한 조합에 두 큐가 동시에 열릴 수 있다. HIDDEN은 어느 쪽이든 즉시 집행, RESTORED는 양쪽 모두 해제되어야 노출 복귀. 생성자 통지·이의 제기 경로는 공통.

### Flow 7 — 킬 스위치 사유 분리
- 권리 사유(권리자 실행)와 법규/사기 사유(플랫폼 Legal/Ops 실행)를 `reason_class`로 분리. 대상에 원본 이미지 추가(파생 팩 전체 하드 전파). 후속 집행(숨김/환불/통지)은 사유와 무관하게 플랫폼이 수행.

---

### Flow 8(신규) 부정 이용 탐지 → 조사 → 집행
1. 시스템: 결제·발행·미션·랭킹·유일키 이벤트에서 `fraud_signal` 생성(속도, 다계정, 자기거래, 카드 테스트, 환불 악용, 랭킹 파밍, 유일키 선점, 스템 선택 급증, 외부 공유 적중).
2. 시스템: `HIGH` 신호 또는 누적 점수 초과 시 케이스 개시, 관련 이벤트 `FLAGGED` → 정산 배치·팬 인센티브·랭킹·히트맵·공동 최소 보장 산정에서 제외, 권리자 몫 `FRAUD_REVIEW` 보류.
3. Trust & Safety 조사자: 증거 수집, 영향 권리자 테넌트 확인 → 판정자(다른 계정): `CONFIRMED` / `CLEARED`.
4. `CLEARED` → 보류 해제(다음 배치 편입). `CONFIRMED` → 집행(역분개·조합 무효·유일키 회수·포인트 회수·계정 정지/퇴출·필요 시 외부 공유) + 영향 권리자 통지. 대상자는 14일 내 1회 이의 제기.
5. 팬 앱: 보류 중 결제는 "결제 확인 중"으로만 안내(`FRAUD_REVIEW`), 사유·점수 비노출.

### 5.6 `[BO-13]` 권리 구조 통합 인스펙터 (플랫폼 운영 4.0, 신규)

**목적**: 플랫폼 운영자가 관리 정보(파티·원본 권리 이미지·팩 정책)를 편집하지 않고도 테넌트 → 파티 계층 → 작품 → 원본 권리 이미지(L0) → 팩(L1) → 정산 라인을 한 화면에서 연계 조회하고, 정산 이슈를 권리 근거까지 역추적한다. 기존 2.2 "테넌트별 권리구조 조회"는 이 화면의 파티 노드 상세로 **이관**한다.

**공통 규칙**
- 화면 전체 READ-ONLY. 생성/수정/삭제/승인/활성화 버튼을 두지 않는다. 허용 액션은 `무결성 재검사`, `검증 리포트 열기`, `권리자에게 수정 요청`(알림만), `열람 감사 보기`, `CSV 내보내기(마스킹 유지)` 5종.
- `tenant.ops_delegation` 위임이 있어도 이 화면에서는 편집 모드가 열리지 않는다(대행 편집은 권리자 콘솔 대행 모드).
- 지급 계좌·세무 정보는 기본 마스킹. 마스킹 해제 토글은 `PLATFORM_FINANCE` 역할에만 노출되며, 사유 입력 다이얼로그 → `inspection_audit_log(pii_unmasked=TRUE)` 기록 후 해제된다.
- 모든 노드/행은 클릭 가능한 링크이며, 어떤 노드에서든 정산 라인까지 클릭 5회 이내로 도달해야 한다.
- 무결성 배지는 `v_rights_structure_tree.integrity_flags`를 그대로 사용한다(`CLAIMANT_DRIFT`, `PARTY_CEILING_EXCEEDED`, `CONTRACT_RANGE_VIOLATION`, `MEMBER_LINK_INVALID`, `PARTY_UNVERIFIED`, `PAYOUT_ACCOUNT_MISSING`, `BASE_IMAGE_STALE`, `INHERITANCE_VIOLATION`, `KYB_REQUIRED`, `SOURCE_INTEGRITY_BLOCKED`, `FRAUD_REVIEW`).

### 5.7 `[BO-15]` 소스 무결성 검사 큐 (플랫폼 운영 3.3, 신규) + 권리자 소명

### 5.8 `[BO-14]` 부정 이용 조사 (플랫폼 운영 5.3 Trust & Safety, 신규)

**5.4 무결성 지표 공유 레지스트리(SHARE)** — 표 1개로 충분: 방향(IN/OUT) · 상대 기관 · 지표 유형 · 해시 · 신뢰도 · 근거 케이스 · 법적 근거 · 만료일. OUT 등록은 `CONFIRMED` 케이스의 `HIGH` 지표만 선택 가능하며 원문 입력 필드를 두지 않는다.

**1.1 대시보드 무결성 KPI 위젯(MEASURE)** — `v_integrity_kpi`: 케이스 정밀도, 오탐률, 보류·회수 금액, 평균 판정 시간, 재발률, 소스 BLOCK/REVIEW 비율, KYB/KYC 충족률, 팬 인센티브 누수율.

### 5.10 `[BO-17]` 동의 요구 매트릭스 (권리자 콘솔 5.2 · 플랫폼 2.3)

### 5.11 실연자 포털 동의 흐름 (모바일, 수정 지시)

1. **T0 원천 동의 서명** (녹음 단위 1회): 동의서 열람 → **등급 선택**(G1/G2/G3, 등급 안에서 개별 행위 해제 가능) → 지역·기간·교체/타 멤버 조합/솔로 구간 허용 → 인격권 특약 확인 → 본인 인증 서명. 주실연은 기획사 연서 완료 후 서명 버튼 활성, 미성년은 법정대리인 서명 단계 추가.
2. **T1 개인 상한 확인** (원본 이미지 확정 시 1회): T0 범위로 자동 채워진 이 이미지의 상한(파트·지역·등급)을 확인하고 필요하면 좁힌 뒤 확인. T0보다 넓힐 수 없음.
3. **T2 팩 알림** (기본 AUTO): 새 팩이 내 상한 안에서 열리면 알림만 받는다("내 목소리가 ○○ 팩에 쓰입니다"). 서명 불필요. 상한 밖 팩은 애초에 내가 제외된다.
4. **재동의**: 약관 중대 개정·이미지 개정(내 스템 변경)·만료 30일 전에 요청 카드 표시. 새 동의 서명 시 이전 동의는 대체(SUPERSEDED).
5. **철회**: T0 철회는 이 녹음의 모든 이미지·팩에 전파(신규 조합 즉시 차단, 기존 자산은 유예 30일 규칙).
