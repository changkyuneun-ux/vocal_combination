# 요건 추적표

MVP 진행계획 M0의 산출물이다. 설계 문서의 구조·정책 항목마다 MVP의 구현 위치, 그것을 확인하는 시험, 상태를 잇는다. "모든 설계 구조·정책 반영"은 이 표의 모든 행이 "구현됨"이 되고 M6 인수 시험을 통과하는 것으로 판단한다.

- 근거 문서: [아키텍처](../../../00_프로젝트_개요/시스템_아키텍처_및_업무분리안_20261012.md)(약칭 A), [원천 문서 설계](../../../00_프로젝트_개요/원천문서_관리와_권리·정책_입력·조회_설계_20261015.md)(S), [Dynamite 예시](../../../00_프로젝트_개요/예시_Dynamite_2차이용_권리생성에서_지급까지_20261012.md)(E), [MVP 진행계획](../../../00_프로젝트_개요/MVP_진행계획_Dynamite데모_20261016.md)(M)
- 경로: 코드는 `services/rights-core/src/` 기준(`rc/`), 시험은 `services/rights-core/test/`(`t/`)와 `apps/*/e2e/`(`e2e/`)
- 상태: **구현됨** = 코드와 시험이 있다. **M2~M6** = 그 단계에서 갖춘다. 구현됨이어도 MVP 배포 구조에서 다시 확인하는 행은 "확인"에 M 단계를 적었다

## 남은 결정

- [x] **MD8** 72시간 발행 승인 큐를 MVP에 넣을지 (막는 항목: M5)
  - 제안: 넣지 않는다. 지금 발행은 게이트 통과 즉시 봉인되고, Dynamite 시나리오에도 승인 큐 단계가 없다. 권리자 포털 메뉴에 "발행 조합" 조회만 두고, 승인 큐는 상용 단계 작업으로 아키텍처 문서 다음 작업 목록에 올린다
  - 결정(2026-10-16, 사용자): 넣지 않는다(제안대로). 발행은 게이트 통과 즉시 봉인하고, 권리자 포털에는 발행 조합 조회만 둔다. 승인 큐는 아키텍처 문서 다음 작업 18번(상용 단계)으로 올렸다
