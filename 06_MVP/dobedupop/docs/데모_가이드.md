# dobedupop MVP 데모 가이드 — Dynamite 2차 이용

BTS "Dynamite" 2차 이용을 빅히트 뮤직 테넌트·멤버·운영자가 각자 로그인해 권리 등록부터 지급까지 보여 준다. 가상 사례다. 곡 크레딧(작사·작곡 David Stewart·Jessica Agombar)·멤버·가창 시간만 실제이고, 지분·계약·가격·판매량은 가정이다.

## 띄우기

```bash
cd 06_MVP/dobedupop
cp deploy/env/demo.env.example deploy/env/demo.env     # 처음 한 번. RC_DOC_KEY: openssl rand -base64 32
docker compose -f deploy/compose/compose.demo.yml --env-file deploy/env/demo.env up -d --build
```

| 주소 | 화면 |
| --- | --- |
| http://demo.dobedupop.localhost | 데모 진행판(단계 실행·페르소나로 앱 열기) |
| http://portal.dobedupop.localhost | 권리자 포털(권리 테넌트) |
| http://partner.dobedupop.localhost | 참여 기관 화면(신탁단체·유통 파트너) |
| http://artist.dobedupop.localhost | 실연자 앱(휴대폰 화면 크기로 보면 좋다) |
| http://ops.dobedupop.localhost | 운영 백오피스 |

`*.localhost` 주소는 hosts 파일 없이 이 컴퓨터로 연결된다(Chrome·Edge·Firefox). Safari에서 열리지 않으면 Chrome을 쓴다.

## 진행

1. 데모 진행판에서 **처음부터 다시** → 단계를 하나씩 **실행**하거나 **남은 단계 모두 실행**. 전체 실행은 약 3~4분이다(3월 구매 2,201건을 넣고, 지급은 가상 PSP가 1분 뒤 완료 통지).
2. 각 단계 카드의 버튼(예: "포털: 권리 요약")을 누르면 그 단계를 보여 줄 앱이 그 페르소나로 로그인된 채 새 탭에 열린다.
3. 오른쪽 "페르소나로 앱 열기"에서 사람을 바꿔 본다. 같은 데이터를 사람마다 다르게 보는 것(테넌트 격리·역할)이 시연 포인트다.

가상 시계는 단계마다 앞으로 간다(1/1 온보딩 → 2/1 정책 활성화 → 2/15 발행 → 4/1 정산 → 5/1 지급).

## 페르소나

| 사람 | 앱 | 볼 것 |
| --- | --- | --- |
| 빅히트 관리자(`usr_bh_admin`) | 포털 | 내 조직(상태·확인 항목·당사자), 담당자 계정 초대·역할·잠금, 위임 대행 설정, 신탁·유통 연결 |
| 빅히트 권리 편집(`usr_bh_rights`) | 포털 | 권리 요약(문장 + 근거 문서), 원천 문서, 확인 요청, 표준 계약, 정합성 점검, 발행 조회, 명세(레이블·소속사) |
| 빅히트 정책 편집·승인·활성화 | 포털 | 분배 규칙 — 세 사람이 나눠서 편집·승인·활성화 |
| 정국·진 등 멤버(`usr_member_*`) | 실연자 앱 | 동의·계약 서명, 내 목소리가 쓰인 조합, 수익(위임 전 내 기여분), 알림 |
| 운영(`usr_ops`) | 운영 | ⑧ 파이프라인 관제(이상거래 1건 보류 등), 한 건 추적, 확인 요청(작가 지분 원문 대조) |
| 정산 담당(`usr_settle`) | 운영 | 정산 배치(실행 → 독립 재계산 → 확정), 원장, 지급 run, 명세 |
| 플랫폼 온보딩 담당(`usr_rights`) | 운영 | 권리 테넌트·참여 기관 등록, 확인 항목·상태(신청 → 확인됨 → 활성), 첫 관리자 발급, 당사자 등록, 해외 작가와의 작품 이용허락, 신탁 연결 제안, 위임 대행 |
| 가상 신탁단체 관리자(`usr_cmo_admin`) | 참여 기관 | 신탁 연결 확인(데모는 제안 상태로 남겨 둔다), 신탁 작품, 명세 |

데모 환경에만 페르소나 빠른 로그인이 있다. 실제 로그인(운영 = 비밀번호 + 인증 앱 코드, 포털·참여 기관 = 비밀번호, 실연자 = 본인 인증 코드)도 같은 화면에서 된다.

## 온보딩(테넌트 정책 — 권리 테넌트·참여 기관·개인·플랫폼 운영)

권리를 등록하려면 권리 테넌트가 있어야 하고, 신탁단체·유통 파트너는 권리를 만들지 않는 참여 기관이며, 실연자·팬은 테넌트 없이 개인 계정으로 일한다. 근거: [테넌트 관리 기준과 정책](../../../00_프로젝트_개요/테넌트_관리_기준과_정책_20261019.md).

| 화면 | 할 수 있는 일 |
| --- | --- |
| 운영 → 9 온보딩 → 권리 테넌트 / 참여 기관 | 목록(유형·상태·사업자번호·계정·당사자), 등록(신청 상태로) |
| 운영 → 조직 상세(예: 빅히트 뮤직) | 확인 항목 체크(사업자·대표자·플랫폼 계약·권리 보유 증빙 / 신탁 허가·유통 계약), 상태 바꾸기(확인됨·활성·정지·재개·해지, 사유), 첫 관리자 발급 → 초대 링크, 당사자 등록, 연결, 위임 대행 현황 |
| 운영 → 개인 계정 | 실연자·팬 계정, 독립 아티스트 1인 온보딩(본인 인증한 개인 → 1인 권리 테넌트) |
| 운영 → 10 관리 → 운영 인력 | 운영·정산·온보딩·컴플라이언스·법무 계정(권리 결정 역할은 줄 수 없다) |
| 포털·참여 기관 → 담당자 계정 | 조직 관리자가 담당자를 초대하고 역할·잠금을 관리한다 |
| 포털 → 위임 대행 | 조직 관리자가 플랫폼에 맡길 업무(권리 데이터 등록 대행)를 정하고, 대행 기록을 본다. 플랫폼 온보딩은 포털 머리글의 "위임 대행"으로 그 테넌트 권한으로 일한다 |
| 연결(세 앱) | 신탁 연결(작가 ↔ 신탁단체)·유통 연결(권리 테넌트 ↔ 유통 파트너) 제안·확인·끝내기, 상품 대응 제안·확인 |

상태의 뜻: 신청 = 관리자만 열람, 확인됨 = 등록은 되지만 팩·정책 활성화와 판매는 안 됨, 활성 = 모두, 정지 = 판매 중지·지급 보류, 해지 = 로그인 불가·연결 종료. 데모 진행판의 온보딩 단계가 빅히트를 신청 → 확인됨으로, 운영 확인 단계가 권리 보유 증빙(녹음 계약서 원문)을 확인해 활성으로 올린다.

**신탁 연결 시연**: 참여 기관 화면에 가상 신탁단체 관리자로 들어가 "연결"에서 `lnk_trust_demo`(작가 David Stewart)를 확인하면, Dynamite에 작가 → 신탁단체 작품 몫 위임이 자동으로 생긴다. 이 데모 정책은 작품 몫을 위임대로 보내지 않으므로 포털 "정합성 점검"에 경고 3개가 뜬다 — `TRUST_NOT_ROUTED`(정책이 위임대로 보내지 않음), 위임의 근거 문서(신탁 계약) 없음, 신탁단체 지급 정보 없음(금액은 그대로). 신탁단체는 "신탁 작품"에서 Dynamite의 작품 정보·작가 지분·이용 실적만 본다. 확인하면 데모 진행판의 숫자 비교와 무관하게 데이터가 바뀌므로, 다시 보려면 "처음부터 다시".

데모 페르소나 계정은 빠른 로그인으로 들어가므로 계정 목록에 "초대 수락 대기"로 보인다 — 실제 비밀번호 로그인을 보려면 "초대 링크 다시 만들기"로 링크를 받아 비밀번호를 정한다.

## 지금의 한계

- 시연 단계는 데모 진행판이 API로 실행한다. 같은 일을 화면에서 직접 해 볼 수도 있지만(예: 새 곡 등록), 단계 진행과 섞으면 진행판이 상태를 모른다 — 그럴 때는 "처음부터 다시".
- 4월 감상 매출(재생 비중 배정)과 동의 철회·노출 중지 시연 단계는 아직 진행판에 없다.
- 개발용 PSP의 실패 주입(지급 실패 시연)은 역할을 나눈 데모 스택에서 워커에 닿지 않는다.
