1. 개요 및 배경

  • 디지털 성우 아바타 정의: 단순한 텍스트 음성 변환(TTS)을 넘어, 실제 성우의 고유한 목소리 톤, 연기 스타일, 감정 표현을 딥러닝으로 학습하여 재현하는 AI 모델입니다.
  • 기술적 차별성: 기존 TTS의 기계적인 억양을 탈피하고, CosyVoice2의 제로샷 복제 능력과 openSMILE 기반의 정밀 감정 파라미터 추출 기술을 결합하여, 미세한 감정(떨림, 숨소리 등)까지 제어 가능한 시스템을 구축합니다.
  • 산업 적용 목표: 급성장하는 한국어 콘텐츠 시장(웹툰 무빙툰, 오디오 드라마, 게임 캐릭터 보이스, 자동 더빙)에 고품질/저비용의 음성 솔루션을 제공하는 것을 목표로 합니다.

4. 데이터 수집 및 보이스 라벨링

4.1 수집 전략

  • 성우 섭외: 다양한 연기 폭을 가진 전문 성우(남/녀 각 2명 이상) 섭외.
  • 녹음 환경: 전문 방음 스튜디오, 샘플 레이트 44.1kHz / 16bit 이상, Mono 채널.
  • 데이터량: 성우당 최소 1시간 이상의 청정 음성 데이터 (감정별 밸런스 유지).

4.2 음성 클립 분류 체계

5. 메타데이터 스키마 및 데이터셋 구조

5.1 JSON 스키마 필드 정의

카테고리 필드명 (Key) 타입 필수 설명 및 예시
기본식별 clip_id String Y P01_C03_S05_T01

라이선스 usage_rights String Y Commercial-All (전체 상용)

5.2 openSMILE eGeMAPS 파라미터 추출 항목

  • Pitch (F0): 목소리의 높낮이 변화. 억양과 강조점을 분석.
  • Energy (RMS): 음성의 크기 및 에너지 레벨. 감정의 강도(Intensity) 측정.
  • Voice Quality (Jitter/Shimmer): 성대의 불규칙한 진동. 떨림, 거친 소리 등 감정적 질감 분석.
  • Spectral (MFCC): 음색(Timbre) 특성. 화자 고유의 소리 특징.
  • Prosody: 발화 속도, 포즈(쉼) 길이, 리듬감 등 운율적 특징.

6. 모델 아키텍처 및 기술 스택

6.1 3-레이어 핵심 스택

Layer 1: 생성 엔진

CosyVoice2

- 다국어 Zero-shot 복제
- Instruct 모드 (자연어 프롬프트)
- 기본 음성 합성 담당

Layer 2: 제어 엔진

EmoSteer-TTS

- 모델 재학습 불필요
- 감정 벡터 조작 (Alpha Scale)
- 복합 감정 혼합 (슬픔+분노)

Layer 3: 분석 엔진

openSMILE

- eGeMAPS 표준 파라미터
- 88개 음향 특징 추출
- 데이터 정량화 및 라벨링

6.2 보완 전략 (Two-Track Strategy)

  • Track A (고정밀 복제): GPT-SoVITS v3 활용. 1분 내외의 데이터로 화자 유사도 극대화. 일반 대사 처리에 최적 (RTF 0.028).
  • Track B (감정 연기): CosyVoice2 Instruct + RVC 활용. 복잡한 감정 연기는 CosyVoice2로 생성 후, RVC로 성우 본연의 음색 보정.
  • 보조 모델: F5-TTS. 격노, 극도의 공포 등 기존 모델이 표현하기 어려운 특수 감정 생성 시 활용.

6.3 감정 제어 3단계 레이어

  1. Level 1 (자연어): "슬프게 말해줘", "화난 목소리로" 등 텍스트 프롬프트 사용 (CosyVoice2).
  2. Level 2 (벡터 조작): EmoSteer를 통해 감정 벡터의 강도 조절 및 감정 간 보간(Interpolation).
  3. Level 3 (방향 제어): EmoKnob을 사용하여 특정 성우의 중립/감정 쌍에서 추출한 방향 벡터 적용.

10. 품질 평가 및 검증 방법

  • MOS (Mean Opinion Score): 청취자 주관 평가 (5점 만점). 목표 4.5점 이상. (CosyVoice2 논문 기준 5.53 참조)
  • Speaker Similarity (화자 유사도): 원본 성우 음성과 생성 음성의 유사도 측정. 목표 80% 이상.
  • SER (Speech Emotion Recognition): AI 모델을 통해 생성된 음성의 감정 분류 정확도 자동 평가.
  • WER (Word Error Rate): 발음 정확도 측정. 대본과 생성 음성의 텍스트 일치율 검증.

11. 보안 및 라이선스 관리

  • 성우 권리 보호: 성우 동의서(Consent Form) 필수 징구. 녹음 목적, 사용 범위(플랫폼, 기간), 2차 저작권 동의 버전을 체계적으로 관리합니다.
  • 라이선스 관리: 오픈소스 모델(CosyVoice2 - Apache 2.0, GPT-SoVITS - MIT 등)의 라이선스 준수 여부를 확인하고, 상용화 가능 범위를 명확히 합니다.
  • 데이터 보안: 원본 음성 데이터는 암호화하여 저장하며, 인가된 인원만 접근 가능하도록 권한을 제어합니다.

13. 실증 운영 시나리오

Scenario 1: 오디오 드라마 자동 더빙

  • 입력: 웹소설 대본 1화 분량 (약 300 문장).
  • 처리: 대본 파서가 지문 분석 → 감정 라벨 자동 태깅 → 최적 모델(Cosy/GPT) 라우팅 → 음성 생성.
  • 출력: 전체 오디오 트랙 및 씬별 감정 정확도 리포트 생성.

Scenario 2: 게임 캐릭터 음성 대량 생성

  • 입력: RPG 게임 NPC 대사 데이터베이스 (500줄).
  • 처리: 캐릭터 프로필(성격, 역할) 매핑 → EmoKnob 벡터 일괄 적용 → 배치(Batch) 생성.
  • 출력: 캐릭터별 폴더링된 음성 패키지 (Asset).

Scenario 3: PD 실시간 피드백 루프

  • 입력: 연출 PD가 컨트롤러 UI 조작 (슬픔 강도 3 → 5로 조정).
  • 처리: 변경된 파라미터를 즉시 모델에 반영하여 재생성 (On-the-fly).
  • 출력: 실시간 미리듣기(Preview) 제공으로 빠른 의사결정 지원.

14. 주요 산출물 목록

  • 데이터 레이어: 성우별 원본/가공 음성 DB, eGeMAPS 파라미터 리포트, 통합 메타데이터셋(JSON), 감정 방향 벡터셋, 라벨링 가이드.
  • 모델 레이어: Speaker Identity 임베딩 파일, 감정 프롬프트 템플릿셋, EmoSteer 통합 추론 엔진, GPT-SoVITS 파인튜닝 모델.
  • 시스템 레이어: 대본 파서 엔진, PD용 컨트롤러 UI, SER 자동 평가 모듈, MVP 전체 파이프라인 코드.
  • 문서 레이어: 시스템 설계서, API 명세서, 품질 평가 결과 보고서, 성우 계약서 및 동의서, 실증 시연 영상.

15. 예산 및 인프라 고려사항

  • GPU 인프라: NVIDIA A100 또는 H100 (학습 및 고속 추론용). 초기에는 클라우드(AWS/GCP) 활용, 추후 온프레미스 전환 고려.
  • 스토리지: 고음질 WAV 원본 및 버전별 모델 저장을 위한 대용량 스토리지 및 백업 시스템.
  • 개발 환경: Python 3.10+, CUDA 11.8+, Docker 기반 컨테이너 환경 구축.
  • 예산 항목: 인건비(개발/성우), GPU 클라우드 비용, 녹음 스튜디오 대관료, 소프트웨어 라이선스, 법무 자문료 등.

  • 다국어 확장: CosyVoice2의 다국어 기능을 활용하여 일본어, 영어, 중국어 성우 아바타 개발 및 글로벌 진출.
