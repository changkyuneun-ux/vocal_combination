# 보컬 커스터마이징 데모 UI 디자인 리뷰

대상: https://dobedopopfront.vercel.app/
검토 범위: 앨범 리스트 → 커스텀 확인 모달 → 보컬 조합 빌더 → 프리뷰/믹스/검증 → 발행 검증 결과
관점: 컬러 · 아이콘 · 정보 배치 · 가독성 · 사용성

---

## 종합 요약

전체 흐름과 화면 구성은 직관적인 편이나, 다음 4가지가 사용성·가독성을 떨어뜨리는 핵심 요인입니다.

1. **컬러 위계 부재** — 모든 버튼이 동일한 보라색이라 "지금 눌러야 할 것"이 보이지 않음
2. **명칭 불일치** — 같은 기능을 화면마다 다르게 부름(조합 만들기 / 보컬 커스텀 / 커스텀 뮤직)
3. **검증 시점이 늦음** — 규칙 위반을 빌더 단계가 아니라 맨 마지막 검증에서야 알게 됨
4. **미완성 텍스트(플레이스홀더) 노출** — "00개", "아티스트 명" 등이 그대로 보임

---

## 1. 컬러

- **단일 보라색 과다 사용 → 위계 없음.** `커스텀 하기`, `검증하기`, `수정하기`, `AI Customize`, `프리뷰`, `PLAY`가 전부 같은 채도의 보라색. 1차/2차 액션 구분이 안 됨.
  - 개선: 1차 액션만 솔리드 보라, 2차 액션은 아웃라인/회색, 보조 링크는 텍스트 버튼으로 단계화.
- **배지 대비 부족.** `한정발행`(연보라 배경)·`상업 발행 가능`(회색)·`공개범위 자유` 텍스트가 옅어 읽기 어려움. 배경/글자 대비 WCAG AA(4.5:1) 미달로 보임.
- **"믹스 컨트롤" 섹션 라벨**이 흰 배경 위 연보라라 거의 안 보임 → 진한 회색/검정으로.
- **카드와 배경 분리 약함.** 거의 흰색 배경 + 연회색 카드라 경계가 흐릿함 → 카드에 옅은 그림자나 테두리 추가.
- **잘된 점:** 오류 상태의 빨강은 명확하고 적절함.

## 2. 아이콘

- **상단 헤더(검색·알림·메뉴) 라벨 없음 + 의미 모호.** 특히 알림(벨)·햄버거가 이 맥락에서 무엇을 여는지 불분명.
- **Cell/Stem 모드 토글(격자 아이콘)이 가장 큰 문제.** 아이콘만으로 모드 의미를 알 수 없고, 현재 어떤 모드인지 표시가 없음 → 텍스트 라벨 또는 세그먼트 토글(Cell | Stem)로 노출 권장.
- **우측 플로팅 툴바(선택·되돌리기·다시실행)** 아이콘이 작고 대비가 낮음. 비활성(다시실행)이 거의 구분 안 됨.
- **믹스 컨트롤의 슬라이더가 한 줄에 2개**인데 무엇을 뜻하는지(좌/우? 볼륨/팬?) 라벨·수치 없음.
- **저장(플로피디스크)** 은 구식 메타포지만 허용 범위. 단, 저장 후 피드백(토스트)이 없음.

## 3. 정보 배치 · 구조

- **빌더 캔버스 공간 낭비.** 얼굴 격자가 상단에만 떠 있고 화면 절반 이상이 빈 공간 → 격자를 중앙 정렬/확대하거나 컨트롤을 끌어올려 균형 맞추기.
- **격자(24칸)와 하단 멤버 비율(7명)의 관계가 설명되지 않음.** 무엇을 의미하는지 범례·축·안내가 필요(예: "각 칸 = 곡 구간, 색/얼굴 = 담당 보컬").
- **멤버 비율 막대가 가로 스크롤**이라 일부 멤버가 가려짐. 합계(현재 데모는 103%) 표시도 없음 → 전체 합계와 100% 충족 여부를 항상 노출.
- **명칭 불일치:** 페이지 타이틀 `보컬 커스터마이징`, 빌더 `보컬 조합 만들기`, 프리뷰 `보컬 커스텀`, 모달 `커스텀 뮤직` → 용어 통일 필요.
- **확인 모달에 닫기(X) 없음**, 규칙 텍스트가 빽빽함(`발행 전 필수!...`).

## 4. 가독성

- 보조 텍스트(아티스트명·태그·안내문)의 회색 대비가 전반적으로 낮음.
- 검증 결과 규칙 문장이 **한 줄짜리 긴 법조문형**("...90%미만까지 구성된 조합을 발행할 수 있으며, 1.1.1의 조건이 아닌...") → 번호·불릿로 분해하고 핵심만 강조.
- 검증 결과 우측 `발행 가능 / 확인하기`에 **회색 체크가 떠 있는데 실제로는 오류 상태** → 상태 표시가 모순적. 통과/실패를 색·아이콘으로 명확히.

## 5. 사용성 · 인터랙션

- **검증이 너무 늦다.** 비율 규칙(예: 한 인물 90% 미만, 2인 이상 10% 이상)을 빌더에서 실시간으로 안내하지 않아, 다 만들고 검증 단계에서야 실패를 발견 → 빌더에 실시간 유효성 힌트 추가.
- **검증 로딩 오버레이가 결과 위에 겹쳐 표시됨**(스피너 (4/4)가 이미 노출된 결과 위에 잔류) → 전환 상태 정리 필요.
- **`검증하기` 비활성/로딩 시 진한 보라**로 변해 또 다른 활성 버튼처럼 보임 → 비활성은 회색 처리.
- **AI Customize** 클릭 시 가시적 반응이 없어 동작 여부 불확실(데모 한계일 수 있음).
- 발행 성공 화면이 데모에서 항상 규칙 실패로 도달 불가 → 성공 경로 확인 필요.

## 6. 발견된 버그/미완성

- 검증 결과 모달의 **플레이스홀더 미치환:** "항목 **00개**가 성립되지 않았습니다", "**아티스트 명**", "**아티스트 명**이 10%가 되지 않았습니다" → 실제 값으로 치환.
- 데모 비율 합계가 **103%**(17+13+13+17+17+13+13)로 100% 불일치.
- 반응형 미흡: 모바일 홈 인디케이터가 있는 모바일 앱 레이아웃인데 데스크톱 폭에서 요소가 과도하게 늘어남(슬라이더·카드 간격) → 최대 폭 컨테이너 적용.

## 우선순위 제안

**High (즉시)**
- 버튼 컬러 위계 정리(1차/2차/링크 구분)
- 검증 결과 플레이스홀더("00개", "아티스트 명") 실제 값 치환
- 빌더 단계 실시간 비율 유효성 힌트 + 합계/100% 표시
- 화면 간 용어 통일

**Medium**
- 배지·보조 텍스트·"믹스 컨트롤" 라벨 대비 상향(WCAG AA)
- Cell/Stem 모드 토글에 텍스트 라벨 + 현재 상태 표시
- 검증 로딩 오버레이 겹침 수정, 상태 아이콘 일관화
- 규칙 안내문 불릿화

**Low**
- 빌더 캔버스 여백 균형
- 헤더 아이콘 라벨/툴팁
- 저장 등 액션 피드백(토스트)
- 데스크톱 최대 폭 컨테이너(반응형)
